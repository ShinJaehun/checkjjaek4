# 책짹

![책짹 배너](https://raw.githubusercontent.com/ShinJaehun/checkjjaek3/master/github_banner.png)

책짹은 책을 읽은 사람이 자기 생각을 짧게 남기고, 책과 서재를 중심으로 다른 사람의 독서 흐름을 따라갈 수 있도록 만든 독서 커뮤니티 서비스입니다.

`checkjjaek4`는 레거시 `checkjjaek3`에서 시작한 책 기반 SNS 실험을 다시 정리한 리부트 버전입니다. 예전 버전이 `Post` 중심의 범용 SNS 구조에 책, 사진, 메시지, 그룹을 붙여 가는 방식이었다면, 현재 버전은 처음부터 **책, 서재, 책장, 책짹, 관계 기반 공개 범위**를 중심으로 다시 설계했습니다.

---

## 이 저장소에 대하여

이 저장소는 책짹의 현재 리부트 버전입니다.

- 현재 저장소: <https://github.com/ShinJaehun/checkjjaek4>
- 레거시 저장소: <https://github.com/ShinJaehun/checkjjaek3>

`checkjjaek4`는 새 서비스를 완전히 따로 만든 것이 아니라, 기존 책짹의 문제의식과 방향을 이어받아 Rails 최신 구조에 맞게 다시 만든 프로젝트입니다.

책짹의 핵심 방향은 다음과 같습니다.

- 사용자는 짹을 남깁니다.
- 사용자는 책을 자기 서재에 담습니다.
- 사용자는 책에 연결된 짹, 즉 책짹을 남길 수 있습니다.
- 사용자는 다른 사람의 책과 짹을 관계에 따라 볼 수 있습니다.
- 사용자는 소식받기와 책친구 관계를 통해 독서 흐름을 이어갑니다.
- 사용자의 서재 활동은 피드에서 책활동으로 이어질 수 있습니다.

## 왜 다시 만들었나

레거시 `checkjjaek3`는 Ruby on Rails 기반으로 만들어진 책 중심 SNS였습니다. 당시에는 다음과 같은 기능 방향을 가지고 있었습니다.

- 글 작성
- 책과 연결된 글
- 사진과 연결된 글
- 메시지와 연결된 글
- 댓글
- 좋아요
- 팔로우
- 해시태그
- 그룹
- 그룹 가입/승인/정지
- 관리자 기능

하지만 레거시 구조는 기본적으로 `Post`를 중심으로 여러 종류의 컨텍스트를 polymorphic하게 붙이는 방식이었습니다. 책도, 메시지도, 사진도, 그룹 흐름도 결국 `Post`를 중심으로 확장되었습니다.

이 방식은 빠르게 기능을 붙이기에는 좋지만, 책짹이 정말 다루고 싶은 핵심인 **책을 읽는 사람의 서재, 독서 상태, 책에 대한 감정, 책친구와의 관계, 책짹의 공개 범위**를 명확하게 표현하기에는 한계가 있었습니다.

그래서 `checkjjaek4`에서는 단순히 기존 SNS에 책 기능을 추가하는 방향이 아니라, 책과 서재를 중요한 문맥으로 다루는 독서 커뮤니티로 다시 정의했습니다.

---

## 제품 방향

책짹은 일반적인 짧은 글 SNS가 아니라, 책과 서재가 중요한 의미를 가지는 독서 커뮤니티입니다.

서비스의 중심축은 다음과 같습니다.

- `User`
- `Book`
- `Bookshelf`
- `BookshelfEntry`
- `Jjaek`
- `BookActivity`
- `Follow`
- `BookFriendship`

책짹에서 중요한 것은 단순히 “글을 쓴다”가 아니라 다음 흐름입니다.

1. 책을 찾습니다.
2. 책을 내 서재에 담습니다.
3. 그 책의 상태를 정합니다.
4. 그 책에 대한 감정이나 인상을 스티커로 표시합니다.
5. 필요하면 책짹을 씁니다.
6. 다른 사람의 서재와 책짹을 관계에 따라 봅니다.
7. 소식받기와 책친구 관계를 통해 독서 흐름을 이어갑니다.

## 핵심 용어

### 책

서비스 안에서 공통으로 참조되는 도서 정보입니다.

책 자체에는 개인의 감정, 상태, 공개 범위를 저장하지 않습니다. 같은 책이라도 사용자마다 다른 서재 상태와 스티커, 책짹을 가질 수 있습니다.

---

### 서재

사용자가 자기 책 목록과 독서 상태를 쌓는 전체 독서 공간입니다.

현재 구현에서는 `/users/:user_id/library` 화면이 서재 화면입니다. 서재는 별도 DB 모델이 아니라 화면과 라우팅 개념이며, 내부 데이터는 `Bookshelf`와 `BookshelfEntry`가 담당합니다.

---

### 책장

서재 안의 하위 컬렉션입니다.

현재 구현에서는 기본 책장 “내 책장”과 사용자가 추가로 만든 일반 책장을 `Bookshelf` 모델로 다룹니다. 각 책장은 다음 속성을 가집니다.

- 이름
- 공개 범위
- 색상
- 정렬 순서
- 기본 책장 여부

---

### 서재 항목

사용자가 특정 책을 자기 서재의 특정 책장에 담아 둔 기록입니다.

현재 구현에서는 `BookshelfEntry`가 이 역할을 합니다. `BookshelfEntry`는 다음 정보를 가집니다.

- 사용자
- 책
- 책장
- 대표 상태
- 책장 안 위치
- 스티커 목록

---

### 대표 상태

한 서재 항목이 가지는 기본 독서 상태입니다.

현재 구현에서는 다음 3개를 사용합니다.

- 읽고 싶어요
- 읽는 중
- 읽었어요

대표 상태는 한 책에 대해 하나만 선택할 수 있습니다.

---

### 스티커

스티커는 대표 상태와 별개로, 책에 대한 감정이나 의도를 표현하는 보조 태그입니다.

예를 들면 다음과 같습니다.

- 좋았어요
- 너무 좋았어요
- 마음에 남아요
- 다시 읽고 싶어요
- 추천받았어요
- 추천하고 싶어요

대표 상태는 1개만 가질 수 있지만, 스티커는 여러 개를 붙일 수 있습니다.

---

### 짹

사용자가 남기는 기본 글입니다.

책 없이도 쓸 수 있고, 특정 책에 연결될 수도 있으며, 특정 사용자의 프로필 문맥에서 남길 수도 있습니다.

---

### 책짹

책이 연결된 짹입니다.

도메인 모델은 별도 `BookJjaek` 모델이 아니라 `book_id`가 있는 `Jjaek`입니다. UI 문맥에서는 책에 연결된 짹을 책짹이라고 부릅니다.

---

### 다시짹

다른 사용자의 짹을 인용하고 내 의견을 덧붙여 새 짹을 만드는 기능입니다.

현재 구현에서는 별도 모델을 만들지 않고, `Jjaek`이 `quoted_jjaek`을 참조하는 방식으로 다룹니다. 다시짹은 원문보다 넓게 공개될 수 없고, 원문이 비공개이면 다시짹할 수 없습니다.

---

### 책활동

책활동은 사용자가 직접 본문을 쓴 글이 아니라, 서재 상태나 스티커 변경에서 생기는 활동 기록입니다.

예를 들면 다음과 같습니다.

- 책을 서재에 담음
- 대표 상태를 바꿈
- 스티커를 붙임
- 스티커를 제거함

현재 구현에서는 `BookActivity`가 책활동의 피드용 이벤트 모델 역할을 합니다. 단, `BookActivity`는 현재 상태의 source of truth가 아닙니다. 현재 상태는 `BookshelfEntry`와 `BookshelfEntrySticker`가 담당합니다.

## 주요 기능

### 1. 홈 피드

홈 화면은 짹과 책활동이 함께 흐르는 공간입니다.

현재 홈 피드는 다음을 합성합니다.

- 내가 쓴 짹
- 소식받는 사용자의 공개 짹
- 책친구의 책친구 공개 짹
- 나를 대상으로 한 프로필 문맥 짹
- 나와 책친구의 책활동

피드는 단일 `Post` 테이블이 아니라, `Jjaek`과 `BookActivity` 같은 도메인 모델이 만들어내는 결과물로 다룹니다.

---

### 2. 책 검색

책 검색은 Kakao 책 검색 API를 사용합니다.

검색 결과에서는 다음을 할 수 있습니다.

- 책 제목으로 검색
- 이전/다음 페이지 이동
- 검색 결과에서 바로 서재에 담기
- 이미 서재에 담긴 책인지 표시
- 책장이 여러 개 있으면 담을 책장 선택
- 책 상세 화면으로 이동

책 검색 결과는 `BookSearches::SearchService`와 `BookSearches::KakaoAdapter`를 통해 정규화됩니다.

---

### 3. 책 상세 화면

책 상세 화면은 책 문맥 화면입니다.

책 상세 화면에서는 다음을 확인할 수 있습니다.

- 책 제목
- 저자
- 출판사
- 책 표지
- 설명
- 이 책에 연결된 visible 책짹 목록
- visible 다시짹 수

현재 사용자가 그 책을 자기 서재에 담아 둔 경우에는 다음 기능도 열립니다.

- 대표 상태 수정
- 스티커 수정
- 책짹 작성
- 책장 이동

서재에 없는 책 상세 화면은 읽기 전용으로 표시됩니다. 책 메타데이터와 다른 사용자의 visible 책짹은 볼 수 있지만, 상태/스티커 저장이나 책짹 작성은 열리지 않습니다.

---

### 4. 서재와 책장

책짹의 서재는 사용자의 전체 독서 공간입니다.

현재 구현에서는 다음 구조를 가집니다.

- 사용자는 가입 시 기본 책장 “내 책장”을 가집니다.
- 사용자는 일반 책장을 추가할 수 있습니다.
- 책장은 공개 범위를 가집니다.
- 책장은 색상을 가질 수 있습니다.
- 일반 책장은 순서를 바꿀 수 있습니다.
- 기본 책장은 삭제하거나 이름/공개 범위를 바꿀 수 없습니다.
- 일반 책장은 비어 있을 때만 삭제할 수 있습니다.

서재 화면에서는 책장별 책 목록을 볼 수 있고, 정렬 방식을 선택할 수 있습니다.

지원하는 정렬 기준은 다음과 같습니다.

- 최근 수정순
- 수동 정렬
- 제목순
- 저자순
- 상태순

---

### 5. 책장 이동 모드

책장 간 이동은 기본 서재 화면과 분리된 전용 이동 모드에서 처리합니다.

이동 모드 주소는 다음과 같습니다.

```text
/users/:user_id/library/transfer
```

책장 이동 모드의 방향은 다음과 같습니다.

- 본인만 접근할 수 있습니다.
- 책장이 2개 이상일 때 사용할 수 있습니다.
- 중간/큰 화면에서는 출발 책장과 대상 책장을 나란히 다룹니다.
- 책 카드를 드래그해서 다른 책장으로 옮길 수 있습니다.
- 대상 책장 안 특정 위치에 끼워 넣을 수 있습니다.
- 대상 책장 헤더에 드롭하면 책장 끝에 추가됩니다.
- 작은 화면에서는 드래그 대신 선택 모드와 하단 이동 버튼을 사용합니다.
- 같은 책장 안 수동 정렬은 `sort=manual`에서 처리합니다.

기본 서재 화면은 책을 읽고 관리하는 곳이고, 이동 모드는 책장 정리에 집중하는 곳입니다. 두 화면의 역할을 분리해 서재 화면이 너무 복잡해지지 않도록 했습니다.

---

### 6. 프로필

프로필은 항상 공개 요약 화면으로 해석합니다.

프로필에서는 관계에 따라 보이는 내용이 달라집니다.

| 관계 | 볼 수 있는 내용 |
| --- | --- |
| 아무 관계 없음 | 공개 책장에 담긴 책 목록 |
| 소식받기 | 공개 책장에 담긴 책 목록, 공개 짹 |
| 책친구 | 공개/책친구 범위의 책과 짹, 프로필 문맥 짹 작성 |
| 본인 | 전체 서재, 전체 짹, 모든 작성 진입 |

프로필 화면은 서재 관리 화면이 아닙니다. 책장 탭, 책장 정렬, 책장 관리, 책 이동 UI는 프로필이 아니라 서재 화면에서 제공합니다.

---

### 7. 소식받기와 책친구

책짹에는 두 가지 관계가 있습니다.

### 소식받기

소식받기는 가벼운 단방향 관계입니다.

- 이 사람의 공개 짹을 내 피드에서 보고 싶다는 뜻입니다.
- 상대의 수락이 필요하지 않습니다.
- 공개 짹 중심의 피드 구독 관계입니다.

### 책친구

책친구는 신청과 수락이 필요한 신뢰 관계입니다.

- 책친구 공개 짹을 볼 수 있는 기준입니다.
- 프로필 문맥에서 더 넓은 상호작용을 열어 줍니다.
- 책친구의 책활동을 홈 피드에서 볼 수 있습니다.

소식받기와 책친구는 서로 다른 관계입니다. 팔로우를 했다고 책친구가 되는 것은 아니고, 책친구라고 해서 단순 팔로우와 같은 의미도 아닙니다.

---

### 8. 짹, 책짹, 다시짹

현재 구현에서는 하나의 `Jjaek` 모델이 여러 문맥을 가집니다.

- 일반 짹
- 책짹
- 프로필 문맥 짹
- 다시짹

짹의 공개 범위는 다음 3가지입니다.

- 전체 공개
- 책친구 공개
- 나만 보기

다시짹은 원문보다 넓게 공개할 수 없습니다.

예를 들면 다음과 같습니다.

| 원문 공개 범위 | 다시짹 가능 범위 |
| --- | --- |
| 전체 공개 | 전체 공개, 책친구 공개, 나만 보기 |
| 책친구 공개 | 책친구 공개, 나만 보기 |
| 나만 보기 | 다시짹 불가 |

원문이 삭제되면 다시짹 본문은 보존하되, 다시짹은 나만 보기로 전환됩니다. 공개 화면에는 삭제된 원문 placeholder를 노출하지 않습니다.

---

### 9. 댓글과 좋아요

댓글과 좋아요는 `Jjaek`을 대상으로 합니다.

기본 원칙은 간단합니다.

- 해당 짹을 볼 수 있는 사람만 댓글을 달 수 있습니다.
- 해당 짹을 볼 수 있는 사람만 좋아요를 누를 수 있습니다.
- 상호작용 가능 범위는 공개 범위보다 넓어질 수 없습니다.

---

### 10. 알림

책짹은 `Notification` 모델 기반 알림 inbox를 가집니다.

현재 알림 대상은 다음과 같습니다.

- 책친구 요청
- 프로필 문맥 짹 작성
- 댓글 작성
- 다시짹 작성

알림 화면에 들어가면 읽지 않은 알림이 읽음 처리됩니다. 알림은 원본 도메인 모델을 대체하지 않고, 사용자가 상호작용을 발견할 수 있도록 돕는 inbox 역할을 합니다.

## 설계 원칙

### Post 중심에서 벗어난다

레거시 버전의 모든 것을 `Post`에 연결하는 방식은 유지보수가 어려워질 수 있습니다. 현재 버전은 글, 책 상태, 스티커, 피드 이벤트를 분리해 각 모델의 책임을 명확히 합니다.

### 책과 서재를 중심에 둔다

책짹은 일반 SNS가 아니라 독서 커뮤니티입니다. 따라서 책과 서재는 부가 기능이 아니라 핵심 문맥입니다.

### 프로필과 서재를 구분한다

프로필은 관계 맺기와 공개 요약 화면입니다. 서재는 책장과 독서 상태를 자세히 관리하는 화면입니다.

### 관계에 따라 공개 범위를 다르게 본다

아무 관계 없음, 소식받기, 책친구, 본인 관계에 따라 보이는 책과 짹의 범위가 달라집니다.

### 현재 상태와 피드 이벤트를 분리한다

현재 독서 상태는 `BookshelfEntry`가 담당하고, 피드에 보여줄 활동은 `BookActivity`가 담당합니다. 피드 이벤트가 현재 상태의 source of truth가 되지 않도록 합니다.

### 그룹은 후속 확장으로 둔다

레거시 버전에는 그룹 기능이 있었지만, 현재 리부트 버전에서는 먼저 짹 흐름, 책/서재 문맥, 책활동 기반을 안정화하는 것을 우선합니다. 그룹은 향후 교실 독서 활동, 연구 노트, 보드형 활동과 연결될 수 있는 확장 후보입니다.
