# Book Search MVP

## 상태

이 문서는 현재 제품 흐름과 연결된 **활성 하위 spec**이다.
다만 독립 기준 문서가 아니라, 아래 문서를 전제로 해석한다.

- `docs/specs/bookjjaek_reboot_spec.md`

---

## 목적

외부 책 검색 API와 DB 책 검색을 통합한 `/book_search` 페이지 및
검색 결과에서 책 상세·서재 등록으로 이어지는 흐름은 현재 구현되어 있다.
이 절은 해당 검색 MVP의 목적을 기록한다.

이 단계의 목표는 다음과 같다.

- 책짹의 핵심 정체성인 “책 검색” 기능을 먼저 복원한다.
- 레거시 `checkjjaek3`의 책 검색 흐름을 참고하되, 구현은 현재 공식 API 문서를 기준으로 다시 정리한다.
- 검색 기능을 먼저 작게 고정하되, 현재 제품 흐름에서는 `Book` / `BookshelfEntry` / `Jjaek`와 연결되는 방향을 따른다.

---

## 포함 범위

- Kakao Developers Daum Search Book API 기반 책 검색
- 검색 입력 폼
- 검색 결과 목록 표시
- 검색 결과 pagination
- 최소한의 검색 결과 정규화/표준화
- 빈 결과 처리
- 외부 API 실패 시 안전한 사용자 메시지 처리
- 로그인 사용자 기준 검색 접근
- 얇은 adapter/service 계층 도입
- 검색 결과에서 `책 상세 보기` 진입
- 검색 결과에서 `서재에 담기` import 동작

## 핵심 규칙

- 책 검색은 현재 시점의 Kakao Developers 공식 문서를 기준으로 구현한다.
- 책 검색 엔드포인트는 `GET https://dapi.kakao.com/v3/search/book`를 기준으로 한다.
- 인증은 Kakao REST API 키를 이용한 요청 헤더 방식으로 처리한다.
- Kakao 책 검색 API의 `page`, `size`, `meta.is_end`, `meta.pageable_count`를 사용한다.
- 다음 페이지 존재 여부는 DB 결과의 다음 항목 또는 외부 검색의 `meta.is_end == false`를 기준으로 판단한다.
- 외부 API의 `meta.pageable_count`는 그대로 보존하지만 통합 검색 결과 건수로 표시하지 않는다. 화면에는 전체 건수 안내를 표시하지 않는다.
- `page`는 query string으로 유지한다.
- 검색 폼 제출 시에는 `page` 값을 넘기지 않고, controller에서 기본값 1로 처리한다.
- pagination 링크를 클릭할 때만 `page` 값을 query string으로 유지한다.
- `page` 값이 비정상이면 1로 보정한다.
- `size`는 앱 내부 상수로 고정하며, MVP 기본값은 10으로 둔다.
- 외부 API 호출 코드는 controller에 직접 흩뿌리지 않고, 얇은 adapter/service 계층에서 감싼다.
- 검색 결과는 화면 표시용 데이터로 먼저 사용한다.
- 검색 결과는 최소한 아래 정보를 우선 노출한다.
  - 제목
  - 저자
  - 출판사
  - 썸네일
  - ISBN
  - 소개글 일부
- 검색 결과의 책 썸네일은 공통 책 썸네일 partial을 사용한다.
- 외부 책 주소와 썸네일은 HTTP/HTTPS 및 유효한 호스트만 저장한다. 유효하지 않은 썸네일은 기본 표지로 대체한다.
- 책 검색 결과에서는 표지 전체가 자연스럽게 보이는 것을 우선한다.
- 검색 결과 썸네일은 공통 책 표지 partial에서 전달된 값을 표시한다. UI는 특정 제공자나 URL 변환 규칙에 의존하지 않으며 표지가 없으면 기존 기본 표지를 사용한다.
- 검색 결과의 기본 진입은 `책 상세 보기`다.
- 검색 결과의 `서재에 담기`는 **외부 책 정보를 우리 서비스 DB/서재로 가져오는 import 동작**이다.
- `서재에 담기`는 아래를 포함할 수 있다.
  - `Book` 생성 또는 재사용
  - 현재 사용자의 `BookshelfEntry` 생성 또는 재사용
  - 기본 대표 상태는 비워둘 수 있으며, 사용자가 책 상세 화면에서 직접 선택한다.
- 사용자의 책장이 하나이면 검색 결과 카드의 `서재에 담기` 버튼으로 기본 책장에 바로 등록한다.
- 책장이 2개 이상이면 카드 전용 `서재에 담기` 모달에서 `ui-choice` 라디오로 대상 책장을 선택한다. 기본 책장 우선 순서로 표시하고 기본 책장을 미리 선택한다. 고유 dialog·input ID와 개별 book-modal 범위로 카드 간 충돌을 방지하며 닫기·Esc·긴 책장명 줄바꿈을 지원한다.
- 대상 책장을 선택하지 않으면 기본 책장 “내 책장”에 담긴다.
- 이미 담긴 책이면 중복 생성하지 않고, 기존 `Book` / `BookshelfEntry`를 재사용한다.
- 이미 담긴 책을 다시 POST해도 이번 흐름에서는 책장 이동으로 처리하지 않고 기존 책장 소속을 유지한다.
- 이미 현재 사용자의 서재에 담긴 검색 결과는 중복으로 `서재에 담기`를 보여주지 않는다.
- 등록된 검색 결과는 비활성 버튼으로 표시한다. 실제 BookshelfEntry의 책장이 기본 책장이면 `내 서재에 있음`, 일반 책장이면 `{실제 책장 이름}에 있음`을 표시한다. DB·외부 검색 결과 모두 현재 사용자 소유 BookshelfEntry와 Bookshelf를 일괄 조회하며 다른 사용자의 등록 상태는 사용하지 않는다.
- 검색 결과 등록은 기존 `POST /bookshelf_entries`를 사용한다. Turbo 성공 응답은 현재 카드만 교체하고 비활성 버튼과 실제 책장 이름을 표시하며 페이지 이동 없이 기존 flash를 갱신한다. HTML fallback은 기존 책 상세 redirect를 유지한다. 재등록은 실제 기존 책장을 표시하고 중복 생성·책장 이동·추가 BookActivity 기록을 하지 않는다.
- 동아리의 명시적인 동아리 책짹 작성 버튼에서 모달 검색한 경우 검색·상세/미리보기·개인 서재 담기·Turbo 결과 카드·책짹 작성까지 group_id 맥락을 유지한다.
  검색 대상과 책짹 게시 대상은 구분한다. 개인 서재 등록과 BookActivity에는 동아리 소속을 추가하지 않는다.
- 전역 Navbar 책 검색은 출발 화면과 무관하게 group_id를 전달하지 않는다. search_origin은 복귀 경로만 보존하며 게시 위치를 결정하지 않는다.
- 책 검색 단일 독립 페이지는 아래 검색 화면 정책을 따른다. 동아리 책장은 후속 고려 사항이며 선행 모델을 추가하지 않는다.
- 이미 담긴 검색 결과의 `책 상세 보기`는 새 `Book` / `BookshelfEntry`를 만들지 않고 기존 `Book` 상세로 이동한다.
- 이미 등록된 책의 `책 상세 보기`는 내부 `books/:id`로 이동한다.
- 미등록 책의 `책 상세 보기`는 DB에 쓰지 않는 읽기 전용 미리보기를 표시한다.
- 미등록 책은 검증된 검색 결과로 `서재에 담기`를 제출할 때만 등록한다.
- 신규 검색 결과 등록에는 유효한 canonical ISBN 또는 검증된 외부 책 주소가 필요하다. 기존 Book 및 내부 Book 생성에는 이 조건을 일괄 적용하지 않는다.
- `isbn` 원문은 보존하고, 유효한 ISBN-10은 대응하는 978 ISBN-13으로 변환해 nullable `canonical_isbn`에 기록한다. 복합 ISBN은 유효한 ISBN-13을 우선하되 서로 다른 유효한 ISBN-13이 여러 개면 등록하지 않는다.
- 복합 ISBN의 유효한 ISBN-10 변환값과 우선한 ISBN-13이 다르면 같은 판본의 별칭으로 간주하지 않는다. 기존 무효 ISBN은 원문만 보존하고 `canonical_isbn`은 NULL로 둔다.
- canonical ISBN과 외부 책 주소가 서로 다른 기존 Book을 가리키면 자동 병합하지 않고 오류를 안내한다. 동시 최초 등록은 DB 고유 제약으로 보호하며, 충돌 후 동일 Book이 확인될 때만 트랜잭션 밖에서 한 번 재시도한다.
- 기존 데이터는 병합·삭제하지 않는다. 마이그레이션은 중복 canonical ISBN 또는 외부 URL이 있으면 중단한다. 운영 DB는 배포 전에 별도 사전 감사가 필요하다.
- 검색 결과의 책 정보는 서버가 실제 검색 응답을 받은 뒤 발급한 만료 가능 서명으로 검증한다.
- 기존 공용 Book의 메타데이터는 검색·상세 조회·서재 담기 과정에서 변경하지 않는다.
- `책 상세 보기`만으로는 `BookshelfEntry`를 생성하지 않는다.
- 따라서 검색 결과에서 책 상세로 먼저 들어간 사용자는
  책 정보와 visible Jjaek은 읽을 수 있지만,
  상태/스티커 변경과 Jjaek 작성은 먼저 `서재에 담기` 후 가능하다.
- 검색 결과에서 직접 `Jjaek`를 작성하지 않는다.

## 라우트 / 화면 방향

- 책 검색 입력과 결과는 기존 `/book_search` 단일 독립 페이지에 함께 표시한다.
- 로그인 사용자의 전역 Navbar 책 검색 버튼은 입력 전용 모달을 연다. 검색어를 GET으로 `/book_search`에 제출하며 결과와 자동완성은 모달에 표시하지 않는다.
- 동아리 페이지의 동아리 책짹 버튼도 같은 디자인과 검색 폼의 모달을 연다. 제목은 `책 검색`이며 검색창 위에 `{동아리 이름} 동아리에 게시` 한 줄만 연한 배경의 작은 안내 영역으로 표시한다. 전역 모달에는 이 안내를 표시하지 않는다. 게시 위치는 기존 책 상세 작성 폼에서 변경할 수 있다.
- 검색어가 없어도 검색 폼을 표시하며, 빈 결과 메시지는 검색어가 있고 결과가 없을 때만 표시한다.
- 검색은 `GET` 요청과 query string 기반 흐름을 사용한다.
- 첫 단계에서는 아래 흐름만 만족하면 충분하다.
  1. 로그인 사용자가 검색어를 입력한다.
  2. DB 책을 검색하고 기존 service로 외부 검색을 요청한다.
  3. 결과 목록을 렌더링한다.
  4. 사용자는 결과에서 `책 상세 보기` 또는 `서재에 담기`를 선택할 수 있다.
  5. 결과가 없으면 빈 상태 메시지를 보여준다.
  6. API 실패 시 안전한 오류 메시지를 보여준다.
  7. 결과가 더 있으면 다음 페이지로 이동할 수 있다.
  8. 2페이지 이후에는 이전 페이지로 이동할 수 있다.
- pagination은 GET query string 기반으로 구현한다.
- MVP에서는 `이전` / `다음` 링크만 제공한다.
- legacy `checkjjaek3`처럼 숫자 페이지 범위를 직접 계산하는 UI는 후속으로 미룬다.

## 구현 원칙

- 현재 공식 Kakao Developers 문서를 기준으로 요청 파라미터와 인증 방식을 다시 확인한다.
- 앱 내부에서는 외부 API 의존을 직접 controller에 넣지 않는다.
- service 또는 adapter는 작고 명확하게 유지한다.
- 기본 검색 대상은 제목(`target=title`)으로 시작한다.
- controller는 `query`와 `page`를 정규화해 service에 넘긴다.
- service는 `page`, `size`를 adapter에 넘기고, 결과와 meta를 함께 반환한다.
- adapter는 Kakao API의 `page`, `size`, `is_end`, `pageable_count` 구조를 그대로 활용한다.
- 문자열은 처음부터 locales를 고려한다.
- Turbo 응답 최적화는 이번 spec의 필수 범위가 아니다.
- 지금 단계에서는 “검색이 된다”를 먼저 고정하되,
  리부트 기준에서는 검색 결과를 `Book` / `BookshelfEntry` 흐름과 연결할 수 있어야 한다.
- Kakao REST API 키는 서버 측 설정값으로 관리한다.
- 키 조회와 외부 요청 처리는 controller가 아니라 adapter/service 계층에서 담당한다.

## 테스트 기준

- 비로그인 사용자는 책 검색 기능에 접근할 수 없다.
- 로그인 사용자는 검색어로 책을 검색할 수 있다.
- 검색 결과가 있으면 결과 목록이 정상 표시된다.
- DB·외부 결과는 `검색 결과`라는 한 영역에 기존 순서로 함께 표시한다. 내부 등록 여부로 영역을 나누지 않고 기존 중복 제거 정책을 유지한다. 외부 API 실패 시에도 DB 결과와 안내를 유지한다.
- 검색 결과가 더 있으면 `다음` 링크가 표시된다.
- 마지막 페이지이면 `다음` 링크가 표시되지 않는다.
- 2페이지 이후에는 `이전` 링크가 표시된다.
- pagination 링크는 검색어·page·group_id·검증된 출발 화면을 유지한다.
- 검색 결과 → 책 상세 → 검색 결과와 외부 미리보기 → 등록 → 책 상세 → 검색 결과에서 검색어·페이지·동아리 문맥을 유지한다.
- 검색 페이지의 돌아가기는 출발 화면으로, 책 상세의 돌아가기는 검색 결과로 이동한다. 유효하지 않은 출발 문맥은 안전한 기본 화면으로 복귀한다.
- Navbar 모달은 공통 Navbar에서 한 번 렌더링하며, 열기 시 입력창 포커스·닫기·Esc·포커스 복귀·body scroll lock과 Turbo 이동·캐시 복원 시 닫기를 지원한다. 모바일 메뉴는 모달을 열 때 접고 닫은 뒤 메뉴 버튼으로 포커스를 돌려준다.
- 서재의 검색 링크는 독립 페이지로 직접 이동하며, 검색어 없이도 입력 폼을 표시한다. 동아리 작성 버튼은 현재 작성 권한이 있을 때만 모달을 제공하고 검색 제출 후 독립 결과 페이지로 이동한다.
- 같은 페이지에서 다시 검색하면 최초 출발 화면·동아리를 유지하며 새 검색은 첫 페이지에 표시한다.
- 전역 검색에서 기존 서재 책을 선택하면 출발 화면과 무관하게 일반 책짹이 기본 선택된다. 동아리의 명시적인 작성 모달은 group_id를 유지해 해당 동아리를 기본 게시 위치로 선택한다. 게시 위치는 기존 책 상세 작성 폼에서 바꿀 수 있으며 중복 등록하지 않는다.
- 검색 결과가 없으면 빈 상태 메시지가 표시된다.
- 외부 API 오류가 발생하면 앱이 깨지지 않고 안전한 오류 메시지를 보여준다.
- adapter/service는 응답 데이터를 화면에서 쓰기 쉬운 형태로 정규화한다.
- adapter/service는 Kakao 응답의 `meta.is_end`와 `meta.pageable_count`를 보존한다.
- `서재에 담기`는 `Book`과 `BookshelfEntry`를 생성 또는 재사용한다.
- 이미 담긴 책은 중복 `BookshelfEntry`를 만들지 않는다.
- 책장 하나일 때 바로 등록하고 여러 개일 때 기본 책장이 선택된 라디오 모달을 제공한다. 선택한 일반 책장의 실제 등록·현재 카드만 Turbo 교체·비활성 버튼의 책장 이름·재등록 시 기존 책장과 문맥 유지를 검증한다.

## 현재 단계에서 결정하지 않는 것

canonical ISBN 정규화·충돌·중복 처리는 위 `서재에 담기` 정책에서 확정되어 있으며, 아래 미결정 항목에 포함하지 않는다.

이번 단계에서는 아래를 일부러 고정하지 않는다.

- 작가 정규화
- 검색 결과에서 바로 `Jjaek` 작성까지 허용할지
- 썸네일/소개글을 어느 수준까지 영속 저장할지

이 결정들은 후속 spec에서 다룬다.

---

## 후속 spec 후보

미구현 후속 후보는 작가 정규화와 도서 메타데이터 관리다.
책 상세 상호작용의 추가 정교화도 필요성이 확인되면 별도 spec에서 다룬다.
기존 책 상세 진입과 검색 페이지 구현을 이 후보에 포함하지 않는다.
현재 공용 Book의 메타데이터를 검색·등록 과정에서 변경하지 않는 정책은 유지한다.

## 책 검색 단일 독립 페이지와 DB 검색

- 전역 Navbar는 기존 book-modal 컨트롤러와 GET 검색 폼을 재사용하는 입력 전용 dialog를 제공한다.
  group_id는 보내지 않고 검증된 search_origin만 전달한다. 검색 결과 페이지에서 다시 모달을 열어도 최초 출발 화면만 보존한다.
  동아리 작성 버튼은 동일 partial과 book-modal을 별도 범위와 고유 dialog·입력창 ID로 재사용하고 동아리 안내와 group_id를 명시적으로 전달한다. 열기 포커스·닫기·Esc·포커스 복귀·Turbo 이동/캐시 전 닫기는 공통 동작을 따른다.
  본인 Library 검색은 `/book_search` 페이지로 직접 이동한다.
  검색 입력과 결과·pagination은 기존 독립 페이지에 유지하며 모달 결과 Frame은 사용하지 않는다.
- 검색어가 없는 진입에서는 검색 폼을 정상적으로 표시하고 외부 검색을 요청하거나 빈 결과 메시지를 표시하지 않는다.
- 검색은 기존 폼의 GET 제출로 처리하며 같은 페이지에서 검색어를 바꾸어 다시 검색할 수 있다.
  폼은 group_id·최초 출발 화면을 유지하고 page를 전달하지 않아 새 검색은 첫 페이지에서 시작한다.
  기존 검색 서비스와 결과 카드·pagination·서재 등록 흐름을 유지한다.
- 전역 검색의 서재 등록 책 상세는 일반 책짹 작성 문맥을 사용한다. 명시적인 동아리 작성 모달에서 시작한 검색은
  group_id를 상세·등록·작성에 유지한다. 이미 서재에 등록된 책은 중복 등록하지 않고 기존 작성 흐름을 사용한다.
- 검색 페이지는 검증된 출발 화면을 `search_origin`으로 전달받아 돌아가기 링크·검색 폼·pagination에 유지한다.
  출발 문맥이 없거나 유효하지 않으면 동아리 문맥에서는 해당 동아리, 그 외에는 본인 서재로 돌아간다.
- 검색 결과의 상세·외부 책 미리보기·서재 등록에는 현재 검색 결과 경로를 `return_to`로 전달한다.
  검색어·페이지·group_id 및 검색 페이지의 출발 문맥을 유지하므로 상세에서 검색 결과로,
  검색 결과에서 출발 화면으로 각각 돌아갈 수 있다. 미리보기에서 등록한 뒤에도 같은 경로를 유지한다.
- 출발 화면과 검색 결과 복귀 경로는 모두 `validated_jjaek_return_path`의 내부 GET 경로·query allowlist와
  현재 권한 검사를 거친다. 검색 결과 경로 안의 `search_origin`은 한 단계만 검증·보존하고,
  그 안의 추가 출발 문맥과 중첩 `return_to`는 전파하지 않는다.
- 로그인 사용자는 기존 DB Book의 제목·저자·출판사를 검색할 수 있다. LIKE 특수문자는 escape하며
  기존 page query를 사용해 페이지당 10권을 조회한다. 서재 소속·스티커 등 개인 정보는 검색 결과에 포함하지 않는다.
- 외부 검색은 기존 service/adapter를 재사용한다. DB 검색과 별도로 수행하며 키 부재·요청 실패·잘못된 응답은
  외부 검색 불가 상태로 표시한다. DB 결과와 검색어·동아리 문맥은 유지한다.
- DB·외부 결과가 동일한 기존 Book을 가리키면 해당 페이지의 DB 결과를 우선한다.
  기존 Book의 상세와 등록은 기존 ID를 재사용하며 메타데이터를 덮어쓰지 않는다.
- 결과 표시는 한 목록으로 통합하되 DB 조회·외부 API 조회의 검색 범위, 정렬과 페이지네이션은 각각 기존 정책을 유지한다. 외부 API 건수를 전체 결과 건수로 표시하지 않는다.
- 외부 결과의 일부 필드가 없어도 카드가 표시된다. 제목·저자·출판사·표지 등의 누락을 처리하되
  등록 시 필요한 제목·검증된 ISBN/외부 주소 조건은 완화하지 않는다.
- 외부 검색·결과 선택·미리보기만으로 DB에 쓰지 않는다. 미등록 책에는 가상의 ID를 부여하지 않고
  기존 signed token 기반 lookup·확인·서재 등록 경로를 사용한다. 서명 만료·사용자 바인딩·ISBN 충돌·중복 방지는 유지한다.
- 명시적인 동아리 작성 모달 제출 시 group_id는 검색·pagination·결과 선택·미리보기·등록·책 상세에 전달한다.
  검색과 상세는 기존 GroupPolicy의 작성 권한을 검사하며 개인 등록 데이터에 group 소속을 추가하지 않는다.
- 결과 카드의 상세 선택은 전체 페이지로 이동한다. 서재 등록의 Turbo 카드 갱신과 HTML 등록·redirect를 모두 유지하며,
  갱신된 카드의 상세 링크도 전달받은 검색 결과 복귀 경로를 유지한다.
- 새 외부 제공자 선정·이미지 수집/저장·수동 등록 시스템·검색 결과 직접 책짹 작성은 범위 밖이다.
