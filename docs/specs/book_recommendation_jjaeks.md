# 추천짹 MVP — 통합 짹으로 대체된 역사적 명세

아래 내용은 통합 이전 추천짹의 설계·구현 기록이며 현재 기능 명세가 아니다.
현재의 유일한 작성·첨부 기준은 [unified_jjaeks.md](unified_jjaeks.md)다.
추천짹은 별도 게시물 유형이 아니며 `JjaekBookAttachment`로 책 0~5권을 첨부한다.
과거 전용 작성 단계·route·DOM ID·추천 유형 분류·서재 선행 조건을 이 문서만 보고 복원하지 않는다.
기존 데이터·인용 snapshot은 보존하며 실제 전환 순서는 통합 명세와 운영 문서를 따른다.

## 당시 확정 범위

- 한국어 기능명은 `추천짹`, 동아리 유형은 `동아리 추천짹`으로 통일한다. `추천 목록에 추가` 등 동작 문구는 유지한다.
- 일반 피드와 작성 권한이 있는 동아리의 글쓰기 카드에서 기존 짹·책짹과 같은 배지 형태의 `추천짹`을 선택한다.
- 유형 배지를 누르면 배경을 조작할 수 있는 플로팅 창을 열고, 책 선택과 글쓰기 단계를 같은 창에서 전환한다.
- 검색·재검색·이전/다음 페이지에서도 선택 목록과 순서를 유지하며 게시 전에 제거할 수 있다.
- 이유는 기존 Jjaek의 필수 본문, 200자 제한과 해시태그 처리를 따른다.
- 개인 게시 또는 하나의 동아리 게시를 선택한 진입 문맥대로 생성한다. 동시 게시는 제공하지 않는다.

## 작성 화면

- 새 작성은 1단계에서 시작한다. 창 제목은 `추천할 책 선택하기`이며 검색 input, 추천 목록·개별 삭제,
  `선택 완료`와 닫기 버튼을 제공한다.
- 일반 section에 `role="dialog"`, `aria-modal="false"`를 사용한다. showModal, backdrop, 배경 비활성화,
  body scroll lock이나 focus trap을 사용하지 않으며 배경 페이지를 스크롤·클릭할 수 있다.
- PC는 화면 오른쪽에 제한된 너비의 창을 두고 창 높이는 상단 위치와 화면 높이에 맞춰 제한한다.
  모바일은 하단에서 높이를 최대 48dvh로 제한한다. 높이가 부족하면 창 전체만 스크롤하며,
  추천 목록에는 별도 스크롤 영역을 두지 않는다. 검색 결과는 창 안에 넣지 않는다.
- 최초 검색은 `/book_search?recommendation=1`로 Turbo 이동하고, 추천 검색 페이지 안에서는
  `recommendation-search-results` Frame만 교체하며 `advance`로 검색어·페이지 URL을 유지한다.
  검색 input은 1단계에서만 표시하며 입력 중인 검색어를 연결·해제나 URL 복원으로 덮어쓰지 않는다.
- 로그인 layout의 `recommendation-window`는 `data-turbo-permanent`로 유지한다. 초기 내용은
  `recommendation_composer` Frame으로 로드하며 선택·본문·공개 범위와 단계는 창의 DOM을 기준으로 유지한다.
  서버 임시 캐시 외에 별도 클라이언트 저장소나 전역 상태 저장소는 추가하지 않는다.
  포커스 이동·자동완성 Escape·창 바깥 클릭·스크롤·일반 Turbo 이동은 작성 종료 사유가 아니다.
- 검색 결과에서 추가하거나 창에서 삭제하면 Turbo Stream으로 추천 목록·선택 hidden 입력·배경 검색 결과를
  함께 갱신한다. HTML 응답은 현재 검색어·페이지·동아리·선택을 보존해 검색 페이지로 redirect한다.
  Frame 요청을 이전 작성 페이지로 보내는 `selection_path` 분기는 제거한다.
- Stimulus는 검색·추가·삭제·페이지 이동 전에 창의 최신 선택·동아리 문맥을 요청에 동기화한다.
  페이지 이동 뒤에는 현재 검색어·페이지와 결과 카드의 선택 표시를 동기화한다.
- `선택 완료`는 한 권 이상 선택했을 때 DB 저장 없이 같은 창을 2단계로 전환한다.
  2단계는 책 표지·전체 선택 목록·검색 input 대신 첫 책 제목 일부와 `외 N권`, 전체 권수,
  `책 목록 수정`, 추천 이유 textarea, 개인 공개 범위, 닫기와 최종 `짹` 버튼을 표시한다.
  `책 목록 수정`은 1단계로 돌아가며 다시 `선택 완료`로 2단계에 진입한다.
  단계 전환 때 textarea와 공개 범위를 교체하거나 초기화하지 않는다. 선택 변경은 요약에도 반영되며
  본문·공개 범위·작성 단계·현재 배경 검색어·페이지를 교체하지 않는다.
- 최종 게시의 검증 실패는 작성 내용·공개 범위를 글쓰기 단계에 다시 표시하며 Turbo 요청에서는 창 내용만 갱신한다.
  게시 요청을 보냈다는 이유로 permanent 유지를 해제하지 않는다. 서버가 저장에 성공하면 완료 Stream을 보내고,
  창과 작성 상태를 정리한 뒤 최초 진입 위치로 Turbo 이동한다. HTML 응답도 같은 복귀 위치로 redirect한다.
- 검색 폼·개별 추가/삭제 폼·게시 폼을 중첩하지 않는다. 선택 hidden 입력은 HTML `form` 속성으로 게시 폼에 연결한다.
  기존 책짹 도서 검색 모달·서재 등록 UI와 일반 짹 폼은 유지한다.

## 작성 종료와 최초 위치

- 닫기 버튼, 상단 내비게이션의 다른 메뉴·로고·로그아웃 선택과 게시 성공은 작성 종료다.
  상단의 일반 책 검색 버튼도 먼저 추천짹 작성을 종료한 뒤 기존 검색 모달을 실행한다.
- 종료 시 창을 숨기고 Frame src를 제거해 진행 중인 초기 로드를 취소하며, 추천 선택·본문·공개 범위·단계를
  담은 DOM을 제거한다. 배경 추천 검색 폼의 선택·이전 복귀 위치도 지워 다음 시작에 오래된 상태가 제출되지 않게 한다.
  이전 작성 DOM을 대상으로 예약된 Stream은 종료·새 작성 뒤에 적용하지 않는다.
- 내비게이션 식별은 상단 header의 `data-recommendation-navigation-end` 범위로 한정한다.
  내부 `/book_search` 검색·페이지 이동 및 일반 Turbo 이동을 일괄 종료 이벤트로 취급하지 않는다.
- 최초 위치는 기존 `search_origin` 한 곳에 유지하며 중간 검색·추가·삭제·단계 전환에서 갱신하지 않는다.
  게시 시 기존 내부 GET 경로 allowlist와 현재 권한 검사를 다시 적용한다. 외부·비허용·접근 불가 경로와
  중간 `/book_search`는 복귀 위치로 사용하지 않고 개인 피드 또는 해당 동아리로 돌아간다.
- 개인 피드에서 시작하면 개인 피드, 동아리는 해당 동아리, 프로필을 최초 위치로 전달한 개인 추천짹은 해당 프로필로 복귀한다.
  작성 종료는 DB 초안·Book·Jjaek·추천 연결을 생성하지 않으며 외부 임시 캐시는 기존 사용자 바인딩·만료를 유지한다.

## 추천 책 수

- 추천짹은 중복을 제외한 1~5권을 허용한다. 창은 `추천할 책 (3/5)`처럼 현재 권수를 표시한다.
- 5권이면 새 책 추가를 비활성화하고 안내한다. 삭제 후 다시 추가할 수 있으며 같은 책 재선택은 한 권으로 센다.
- 선택 요청은 중복 제거 후 5권을 초과하면 거부한다. `Jjaek::MAX_RECOMMENDATION_BOOKS`가 제한의 기준이며
  최종 model validation도 5권 초과를 거부한다. 잘못된 게시 요청에서 신규 Book·Jjaek·연결이 부분 저장되지 않는다.

## 검색과 저장 경계

- `BookSearchResults`가 기존 `BookSearchesController`의 DB 검색·외부 검색·pagination 준비를 공유한다.
  일반/추천 책 검색과 추가·삭제 후 배경 결과 갱신은 같은 조회 로직을 사용한다.
- `recommendation=1` 문맥의 별도 결과 카드에는 `추천 목록에 추가`만 표시한다.
  책 상세·외부 링크·서재 등록 동작으로 작성 흐름을 이탈시키지 않는다.
- 일반 검색·서재 등록·책짹 작성에는 추천 목록 동작을 표시하지 않는다.
- 검색·선택·작성 화면에서는 Book을 생성하지 않는다. 선택 POST는 기존 Book ID를 재사용하거나
  사용자에 묶인 검색 결과 서명을 검증해 외부 도서를 임시로 선택한다.
- 외부 선택의 서명된 검색 결과는 사용자별 Rails.cache에 최대 30분 유지하고 화면에는 짧은
  임의 참조값만 전달한다. 서명 원문과 도서 메타데이터를 URL·세션 쿠키에 누적하지 않는다.
  캐시 소실·서명 만료·타 사용자 참조·위변조가 있으면 재선택을 안내한다. 게시 성공 시 캐시 참조를 정리한다.
- 최종 게시 시 선택 정보를 다시 검증해 Book을 조회하거나 초기화하고, 새 Book·Jjaek·추천 연결을
  하나의 transaction으로 저장한다. 본문 검증 실패와 작성 취소 시 새 Book은 생성하지 않는다.
  식별자 부재·ISBN/외부 URL 충돌은 거부하며 기존 메타데이터를 덮어쓰지 않는다.
- 선택과 추천짹 게시는 BookshelfEntry 또는 BookActivity를 생성하지 않는다.
- 선택 목록은 `selected_books[]`에 기존 Book ID 또는 외부 도서 임시 참조를 선택 순서대로 전달한다.
  같은 책은 첫 선택만 유지하고 존재하지 않는 ID·참조가 포함되면 재선택을 안내한다.
  임시 캐시 외에 초안이나 선택 전용 DB 레코드는 만들지 않는다.

## 데이터와 표시

- `Jjaek.recommendation`으로 추천짹을 구분한다. 기존 `book_id`는 단일 책짹 의미를 유지한다.
- `JjaekRecommendation`이 Jjaek과 Book을 연결하고 0부터 시작하는 `position`을 저장한다.
  같은 게시물의 중복 Book과 중복 position은 DB 고유 인덱스로도 금지한다.
- 추천짹은 책 연결을 하나 이상 가져야 하며 단일 book, target_user, ReJjaek 문맥과 혼합하지 않는다.
  새 Book·Jjaek·책 연결은 한 transaction으로 저장한다.
- 공통 카드·상세에 작성자·시각, 순서대로 정렬한 책 표지·제목·저자·`/books/:id` 링크,
  추천 이유·해시태그와 기존 좋아요·댓글 등의 공통 동작을 표시한다.
- 책 상세의 '이 책의 책짹' 목록은 단일 `book_id`의 일반 책짹과 `jjaek_recommendations`로
  해당 책을 추천한 원본 짹을 함께 조회한다. 여러 책을 추천한 짹은 각 책 상세에서 한 번씩 표시하며
  기존 BookScope·GroupContentScope의 조회 경계와 정렬·cursor 페이지네이션을 유지한다.
- 통합 검색과 태그 검색은 `recommendation_jjaeks` 유형으로 조회한다. 일반 짹 유형에는
  추천짹을 포함하지 않으며 책짹은 기존 `book_id` 기준을 유지한다. 운영 목록에서도 별도 유형을 사용한다.
- 기존 본문 수정·삭제·moderation을 재사용한다. 추천짹 편집 페이지에서는 현재 책을 미리 선택하고
  검색·추가·제거로 1~5권의 순서 있는 목록을 수정할 수 있다. 카드의 수정 링크는 현재 페이지를
  유지하고 기존 recommendation_composer Frame으로 편집 데이터를 불러와 오른쪽 추천창을 연다.
  검색을 제출할 때만 기존 책 검색 결과 화면으로 이동한다. 편집 URL 직접 접근의 HTML fallback은 유지한다.
- 수정 모드도 생성과 같은 2단계를 사용하며, 기존 책·이유·개인 공개 범위가 채워진 2단계에서 시작한다.
  `책 목록 수정`으로 1단계에 이동해 검색·추가·제거하고 `선택 완료`로 돌아와도 수정 중인 이유·공개 범위를
  보존한다. 최종 저장은 기존 Jjaek에 PATCH한다. 검색·추가·제거·pagination은 선택 부분과 배경 결과만
  갱신하며 별도 편집용 Frame/Stimulus 인터페이스는 두지 않는다.
- 직접 편집 진입 때 permanent 창을 수정 대상의 상태로 초기화하고 생성/다른 편집과 섞지 않는다.
  검색 전 닫기는 현재 페이지를 유지하고, 검색 후 닫기는 검증된 return_to 또는 원래 Jjaek 상세로 복귀한다.
  요청 revision으로 종료 이전의 늦은 응답을 차단하며 재열기는 현재 DB 값에서 시작한다.
- 수정창 제목은 초기·검색·선택 갱신 후에도 `추천짹 수정`, 저장 버튼은 `수정 저장`이다.
  검색 결과 화면의 돌아가기는 편집을 취소하고 검증된 원래 경로로 복귀한다.
  다른 메뉴/일반 화면 이동은 편집을 취소하고 선택한 목적지로 이동한다.
  이동 전에 창·편집 ID·선택·검색·입력·모드를 비우고 revision을 교체한다. Turbo 캐시/복원에서도
  취소된 permanent 창을 다시 활성화하지 않는다. 같은 수정 대상의 추천 검색 이동은 편집 상태를 유지한다.
- 책 선택은 기존 선택 endpoint·검색·partial과 사용자 바인딩 외부 참조를 재사용한다. 선택 중에는 DB를 변경하지 않는다.
- 최종 수정은 기존 Jjaek의 책 연결·본문·개인 visibility를 하나의 transaction으로 저장한다.
  기존 연결을 교체해 position 고유 제약을 지키며, 실패하면 기존 Book·연결·본문·태그·visibility를 보존한다.
  오류 화면에는 입력 본문·visibility·검증 가능한 선택을 유지한다. 취소 시 원본을 변경하지 않는다.
- 편집 권한은 기존 update policy를 선택과 저장 모두에 적용하고 동아리는 기존 lock 안에서 재인가한다.
  Jjaek ID·작성자·작성 시각·댓글·좋아요를 유지하며 새 알림·활동을 생성하지 않는다. 게시물 유형은 변경할 수 없다.

## 권한과 lifecycle

- 개인 visibility, 피드·프로필 조회와 동아리 작성·조회는 기존 JjaekPolicy 및 scope를 따른다.
- 선택·작성 화면·선택 POST·게시 POST에서 동아리 작성 권한을 검사하고,
  게시 시 기존 동아리 lock 안에서 다시 확인한다.
- 추천 책은 개인 서재에 없어도 선택할 수 있다. 기존 책짹의 서재 등록 조건은 유지한다.
- 다시짹 정책은 `group_sharing_requotes.md`와 `requotes_mvp.md`를 유지한다.
  추천 원문 표시는 추천짹으로 구분하고 기존 원문 삭제 snapshot에도 해당 종류만 보존한다.
  개인 A의 private 전환과 동아리 B/C의 원문 식별 정보 제거는 변경하지 않는다.
- 삭제된 추천짹의 tombstone에는 추천 이유·책 목록을 표시하지 않고 기존 댓글과 접근 경계를 유지한다.

## 제외 범위와 확인 기준

순서 드래그 변경, 임시 저장, 통계·알고리즘은 제외한다.

- 서로 다른 검색에서 여러 책을 골라도 순서·선택이 유지되고 제거·중복 선택이 처리된다.
- 검색 페이지·페이지네이션 이동에서도 창과 선택이 유지되고 추가·삭제 Stream에서 이유·공개 범위·단계를 교체하지 않는다.
- 내비게이션 종료 뒤에는 새 작성이 빈 선택·본문과 기본 공개 범위로 시작하며, 일반 책 검색 모달 동작을 유지한다.
- 5권 제한·중복·삭제 후 재추가·초과 게시 거부와 개인/동아리 최초 위치·안전한 fallback을 확인한다.
- 책 선택 ↔ 글쓰기는 같은 창에서 DB 저장 없이 전환하고 최종 `짹` 게시에서만 저장한다.
- 새 작성은 1단계, 수정은 기존 데이터가 채워진 2단계에서 시작하며 왕복 후에도 이유·공개 범위를 유지한다.
  2단계는 제목·권수 요약만 표시하고, PC·작은 노트북·모바일에서 추천 목록과 창의 중첩 스크롤이 없다.
- 일반/추천 검색의 동작이 섞이지 않으며 선택·게시 후에도 서재와 독서 활동은 증가하지 않는다.
- 외부 도서 선택·제거·작성 취소·검증 실패에서는 Book이 생성되지 않고 최종 게시에서만 생성된다.
- 긴 외부 검색 결과도 짧은 참조값으로 선택을 유지하며 타 사용자·위변조·만료 참조는 저장 전에 거부한다.
- HTML/Turbo 게시와 실패 시 선택·본문 유지, 0권·200자 초과 거부를 확인한다.
- 개인 비공개·동아리 비회원 및 회원 자격 상실 이후 조회·상호작용·게시를 기존 권한대로 제한한다.
- 공통 피드·상세·검색에 추천짹과 각 책 링크가 표시되고 좋아요·댓글이 동작한다.
- 추천 책 1~5권의 표지·제목·저자가 선택 순서대로 표시된다.
- 책 상세에서 일반 책짹과 해당 책의 추천짹을 중복 없이 함께 표시하고, 다른 책의 추천짹과
  기존 scope로 접근할 수 없는 추천짹은 제외하며 페이지 이동에서도 이 경계를 유지한다.
