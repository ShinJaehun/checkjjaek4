# 공통 오류 및 작업 결과 메시지

## 1. 목적과 적용 범위

Rails HTML, Turbo 응답과 Stimulus 비동기 처리에서 성공·실패·검증 메시지의 표시 위치와
전달 책임을 정하는 canonical spec이다. 새 기능과 기존 오류 처리 개선에 적용한다.
공통 flash는 페이지 전체 작업 결과를, 기능별 메시지는 사용자가 해당 위치에서 해결할 문제를 안내한다.

아래는 확정된 공통 정책이며, 모든 기존 화면에 적용이 완료되었다는 뜻은 아니다.
현재 구현과 후속 예정 항목은 8절에서 구분한다. 이번 문서화로 애플리케이션 동작은 변경하지 않는다.
문구는 기존 UI 용어와 ko/en locale을 일관되게 사용한다.

## 2. 메시지 표시 위치 결정 규칙

사용자가 문제를 이해하고 해결할 위치를 기준으로 표시한다. 기존 예외는 7절을 따른다.

| 상황 | 표시 위치 |
| --- | --- |
| 특정 필드의 검증 오류 | 해당 입력 요소 주변 |
| 여러 입력의 조합 등 폼 전체 검증 오류 | 해당 폼 내부 |
| 모달에서 수행한 작업의 오류 | 열린 모달 내부 |
| 검색·첨부 등 개별 기능의 오류 | 해당 기능 영역 |
| 페이지 전체 작업의 성공·실패 결과 | 공통 flash |
| 인증·권한 문제 | 기존 보안 정책에 따른 적절한 인증 화면 또는 flash |

모달 안의 필드 오류도 해당 입력 주변에 표시한다. 공통 flash를 기능 오류의 추가 복사본으로 사용하지 않는다.
성공 메시지를 새로 모든 동작에 추가할 필요는 없으며, 기존 기능이 제공하는 결과 안내에 이 정책을 적용한다.

## 3. 중복 방지와 전달 책임

- 같은 원인의 오류를 필드·폼·모달·기능 영역·flash에 반복 표시하지 않는다.
  서버 검증과 클라이언트 검증이 같은 오류를 감지해도 사용자에게는 한 번만 안내한다.
- 별개 원인의 오류는 구분한다. 예를 들어 책 선택 오류와 외부 검색 실패는 각각의 영역에 표시하며
  한 오류가 다른 오류의 메시지를 덮어쓰지 않는다.
- HTML fallback과 Turbo는 같은 실패 결과를 전달하되 표시 경로는 다를 수 있다.
  서버가 오류의 표시 대상을 정하고, 응답을 소비하는 화면이 그 메시지를 한 번 표시한다.
  Stimulus가 이미 표시된 서버 오류를 다시 flash나 별도 경고로 복제하지 않는다.
- 현재 화면을 렌더링하거나 Turbo로 갱신할 메시지와 redirect 후 다음 GET에서 표시할 flash의
  수명을 구분한다. 표시를 마친 오류가 이후 페이지 방문에 다시 나타나거나 redirect 중 사라지지 않게 한다.

## 4. 실패 후 상태 보존과 성공 판정

- 실패하면 초안·첨부 선택과 순서·검색어·책장 선택·공개 범위 등 비민감 입력과 작업 문맥을 보존한다.
  단, 유효하지 않은 참조나 잃은 권한을 복원하지 않으며 기존 보안·참조 검증을 유지한다.
- 비밀번호·비밀번호 확인 등 민감 입력은 서버 응답·초안 저장소·캐시에서 복원하지 않는다.
- 서버 저장 성공이 확인되기 전에는 성공 메시지를 표시하거나 초안·선택을 완료 상태로 정리하지 않는다.
  redirect를 따라 도착한 페이지의 200 응답만으로 저장 성공을 판단하지 않는다.
- UI의 저장 완료 상태는 서버의 실제 저장 결과와 일치해야 한다. 실패한 변경을 저장된 것처럼 남기지 않는다.
  응답이 소실된 경우에는 저장 실패도 단정하지 않고, 서버 상태를 확인하기 전 성공을 안내하지 않는다.
  책장 이동·정렬의 서버 상태 복구는 7절의 기존 예외를 따른다.

## 5. 오류 상태와 접근성

- 즉시 알려야 할 오류에는 `role="alert"`, 성공·진행 상태나 일부 결과만 제공되는 안내에는
  `role="status"`를 사용한다. HTTP 코드만으로 역할을 일괄 지정하지 않는다.
- 오류가 있는 입력에는 `aria-invalid="true"`를 설정하고, 오류 설명에 고유 ID를 부여해
  해당 입력의 `aria-describedby`로 연결한다. 기존 도움말 연결도 유지한다.
- 색상만으로 오류를 구분하지 않고 오류 내용과 수정 대상을 텍스트로 식별할 수 있게 한다.
- 동일 오류를 여러 live 영역에서 읽거나 `role`과 불필요한 추가 `aria-live`가 중복 안내하지 않게 한다.
  공통 flash wrapper에는 추가 live 속성을 두지 않는다.
- 입력을 수정하고 재검증한 결과에 맞춰 오류 문구·`aria-invalid`·오류 설명 연결을 갱신한다.
  다른 원인의 유효한 오류나 도움말까지 제거하지 않는다.

## 6. HTML, Turbo와 비동기 처리

**HTTP 상태 코드만으로 메시지 표시 위치를 결정하지 않는다.** 코드의 의미, 작업 문맥과
응답을 받는 화면을 함께 고려하며, 기존 endpoint의 응답 계약은 유지한다.

| 경로·상황 | 전달 책임 |
| --- | --- |
| HTML redirect | 다음 GET에서 표시할 flash를 전달한다. 현재 요청 전용 메시지를 redirect 중 소실하지 않는다. 기존 303 fallback 등 기능별 계약을 유지한다. |
| 422 검증 오류 | 제출한 비민감 입력과 오류를 포함한 폼을 렌더링하거나 해당 영역을 갱신한다. 모달·첨부 등 실제 오류 문맥에 표시한다. |
| 403 인증·권한 오류 | 거부를 유지하면서 기존 인증 화면 또는 flash 경로로 안내한다. 인증 여부와 권한 부족을 구분하고, 모든 인증 실패를 403으로 통일하지 않는다. |
| 429 요청 제한 | 7절의 공통 flash 계약과 기존 제한·입력 보존 정책을 따른다. |
| Turbo Frame·Stream | 현재 사용자가 볼 수 있는 올바른 대상에 메시지를 전달한다. 열린 모달 뒤나 갱신되지 않는 페이지 영역에만 메시지가 남지 않게 한다. |
| 네트워크 오류·응답 소실 | 결과를 확인할 수 없음을 해당 작업 문맥에서 안내한다. 저장 여부를 확인하기 전 성공·실패를 단정하거나 초안을 지우지 않는다. |

HTML과 Turbo는 같은 인증·인가·검증·저장 결과를 보장한다. 표시 위치를 바꾸기 위해 HTTP 상태나
서버 권한 판단을 완화하지 않는다. 자동 재시도나 새 오류 저장소 도입은 이 명세의 범위가 아니다.

## 7. 기존 정책의 예외와 보존

- **429는 공통 flash를 유지한다.** [기본 Rate Limit](basic_rate_limiting.md)의 문구·시점·응답·입력 보존을 따른다.
  콘텐츠·동아리 Turbo Stream은 `flash-messages`만 갱신하고, 인증 경로는 기존 인증 화면에서 안내한다.
  모달의 일반 검증 오류와 달리 429를 모달 내부 오류로 전환하지 않는다.
- **책장 이동·정렬의 비동기 실패는 기본 알림창 확인 후 reload를 유지한다.**
  [책장 UI](bookshelf_ui.md)에 따라 서버 상태를 다시 읽고, 일반 이동·묶음 이동 폼의 redirect·flash도 유지한다.
- **책 임시 선택의 HTML fallback은 redirect 후 flash를 유지한다.**
  [통합 짹](unified_jjaeks.md)의 Turbo `book-selection-alert`와 HTML 303 후 flash는 서로 다른 전달 경로이며
  동일 화면에 같은 선택 오류를 함께 표시하지 않는다.
- **기존 권한·보안 정책을 유지한다.** [권한 구조](../architecture/authorization.md)와
  [이메일 초대 가입](registration_invitations_c08.md)의 접근 경계를 바꾸지 않는다.
  오류 안내로 비공개 콘텐츠·계정 존재 여부 등 기존에 보호하던 정보를 추가 노출하지 않는다.
  [책 검색](book_search_mvp.md)의 모달 오류 대상 서명·사용자·출처 검증과 메시지 HTML escaping도 유지한다.

## 8. 적용 현황

기준: `feature/error-feedback-consistency`의 1~8차(`43b764a`)와 9차 구현. 아래 구현 확인은 문서·소스 확인 기준이며
9차 RSpec과 브라우저 검증은 사용자 확인이 필요하다. 이 표는 전 화면의 적용 완료를 의미하지 않는다.
상세 구현 구조는 [현재 시스템](../architecture/current_system.md)을 따른다.

| 상태 | 항목 | 확인된 구현 또는 예정 범위 |
| --- | --- | --- |
| 구현됨 | 짹 저장 성공 판정·초안 보존 | `2cd3458`: 저장 성공 후의 `204`와 `X-Jjaek-Saved-Location`을 함께 확인한 뒤 초안을 정리한다. 실패 redirect는 초안을 지우지 않는다. |
| 구현됨 | 책장 선택 모달 오류 | `67d9461`: 검증된 모달 오류 영역만 갱신하고 열린 모달·선택·작성 문맥을 보존한다. 모달 밖 실패와 429의 flash 계약은 유지한다. |
| 구현됨 | 공통 flash 표현·접근성 | `c1aefcc`: notice는 초록색·status, alert는 빨간색·alert, 기타는 회색·status다. HTML/Turbo가 같은 partial과 단일 wrapper를 사용하며 자동으로 닫지 않는다. |
| 구현됨 | 책 선택 HTML fallback | `1b66599`: 현재 선택 오류를 303 이후 다음 GET의 flash까지 전달한다. |
| 구현됨 | 임시 선택·첨부 검색 오류 분리 | `dfaac85`: 선택 오류와 외부 검색 실패를 각각 표시하고 선택 한도 오류의 중복 문구를 제거했다. 최종 저장·일반 검색 전체에 적용된 것은 아니다. |
| 구현됨 | 비동기 책 이동·정렬 실패 복구 | `32f643a`: 기본 알림창 확인 후 reload한다. 이동의 서버 검증 문구·결과 확인 불가 안내와 정렬의 오류 안내를 제공한다. |
| 구현 완료 | 7차: 가입 403/429 오류 처리 | 무효화된 초대의 POST는 폼 없는 가입 화면에 새 초대 링크가 필요하다는 안내를 한 번 표시하고 403을 유지한다. 가입 전용 429 처리에서는 기존 공통 flash와 429를 유지하며, 현재 유효한 초대에만 폼·이름·handle·약관 선택을 복원한다. 비밀번호·확인은 비우고 재입력을 안내한다. 초대 검증·소비·Rate Limit 카운터는 유지한다. |
| 구현 완료 | 8차: 최종 첨부·일반 검색 중복 오류 처리 | 최종 create/update의 책 첨부 검증 오류는 폼 내부의 첨부 목록에 인접한 alert에만 표시한다. 본문·사진 등 다른 오류는 기존 영역에 유지하고, 본문과 검증 가능한 선택의 순서를 보존한다. 일반 책 검색의 외부 장애는 DB 결과·재검색 폼과 함께 결과 영역의 status로만 안내한다. 임시 선택의 alert·HTML redirect 후 flash와 저장 성공 판정·권한 경계는 유지한다. 구현 완료이며 사용자 실행 검증은 별도다. |
| 구현 완료 | 9차: 입력 오류 접근성 개선 | 짹·댓글 본문은 폼별 고유 ID로 카운터·오류를 연결하고, 실제 본문 오류에만 aria-invalid를 표시한다. 빈 본문·길이 오류는 입력에 맞춰 갱신하며 기타 서버 오류와 setCustomValidity를 유지한다. 카운터의 매 입력 live 안내는 제거하고 설명 연결은 유지한다. 가입 폼과 재설정 링크의 비밀번호 변경 폼은 기존 오류 묶음을 단일 alert로 표시하며, 오류가 있는 필드는 해당 오류 설명에 연결한다. 인증 필드 상태는 서버 재검증 응답을 기준으로 갱신하며, 토큰·폼 전체 오류를 정상 필드에 전파하지 않는다. 재설정 요청의 기존 공통 flash와 7·8차 정책은 유지한다. 구현 완료이며 사용자 실행 검증은 별도다. |

## 9. 신규 기능 구현 체크리스트

- [ ] 사용자가 오류를 해결할 위치가 명확한가?
- [ ] 같은 오류가 중복 표시되지 않고, 별개 원인의 오류는 구분되는가?
- [ ] 실패 후 초안·선택·비민감 입력이 보존되고 비밀번호는 복원되지 않는가?
- [ ] HTML/Turbo 경로 모두에서 메시지가 사용자에게 도달하는가?
- [ ] 성공 확인과 서버 저장 상태가 UI에 일치하는가?
- [ ] 오류 설명 연결·상태 갱신과 중복 음성 안내 방지를 포함한 접근성이 보장되는가?
- [ ] 관련 회귀 테스트가 존재하는가? 표시·상태 보존·실패 경로는 [테스트 전략](../testing/rspec_strategy.md)에 따라 검증하는가?
