# 책짹 개인·동아리 다시짹 설계

## 1. 목적과 기준

이 문서는 기존 `Jjaek`, `quoted_jjaek`, `group_id`를 이용한 개인·동아리 간 공유와 동아리 내부 인용 정책을 정한다. A는 기존 개인 다시짹 동작을 유지하고 B·C의 제품 정책을 정의한다. A·B·C 공유 경로와 원문 삭제 후 처리의 canonical 기준은 이 문서다. 실제 구현 상태는 `../architecture/current_system.md`를 따른다. 기존 동아리 접근 정책은 `groups_mvp.md`, 다시짹 목록 조회와 노출 범위는 `requotes_mvp.md`, visibility와 moderation 경계는 각각 `../architecture/jjaek_visibility.md`, `moderation_mvp.md`를 함께 따른다.

사용자에게는 A·B·C 모두 **다시짹**으로 표시한다. 동작명은 A **내 피드에 다시짹**, B **동아리에 다시짹**, C **이 동아리에 다시짹**이며, 게시물 헤더와 알림에는 읽을 수 있는 범위에서 출처와 목적지를 구분한다. 이 문서의 공유·인용은 기존 데이터 관계와 사용 사례를 설명하는 용어다.

확정 원칙은 다음과 같다.

- 공유 게시물은 **작성자의 의견을 담은 새 `Jjaek`**이다. 원문 본문·책 정보·댓글·좋아요를 복사하지 않고 원문을 참조한다.
- `group_id`가 있으면 그 값은 새 게시물의 **목적지 동아리**다. 동아리의 공개 범위는 개인 `visibility` 값으로 표현하지 않는다.
- 원문을 읽을 권한과 목적지에 작성할 권한을 모두 현재 상태로 검사한다. 공유한 뒤에도 조회할 때마다 원문 및 목적지 권한을 다시 검사한다. 단, 원문 삭제 후 B·C의 동아리 토론에는 5절의 별도 규칙을 적용한다.
- 원문이 다시짹이면 어떤 경로에서도 재인용할 수 없다. 동아리 간 직접 공유와 동아리 → 개인 다시짹 → 다른 동아리 우회 공유도 금지한다. 동아리 간 직접 공유는 향후 확장 후보에도 포함하지 않는다.
- A의 개인 다시짹이 원문 삭제 후 작성자 전용으로 전환되는 기존 규칙은 변경하지 않는다.
- 기존 개인 원문 → 개인 다시짹의 생성·조회·원문 삭제 후 작성자 전용 전환도 B·C 구현의 회귀 방지 대상이며, 세 동작 모두 유지한다.

## 2. 공유 권한 매트릭스

아래의 원문은 모두 삭제되지 않고 숨겨지지 않은 **원본 `Jjaek`**이며, 공유자는 원문을 현재 읽을 수 있어야 한다. `짹`과 `책짹` 모두 같은 규칙을 적용한다.

| 경로 | 원문 | 목적지와 추가 조건 | 결과 |
| --- | --- | --- | --- |
| A. 동아리 → 개인 | active 공개 동아리 원문 | 현재 개인 다시짹 작성 권한 | 허용, 개인 다시짹 1개 생성 |
| 동아리 → 개인 | 승인·비공개 동아리 원문 또는 inactive/pending 동아리 원문 | 개인 | 금지 |
| B. 개인 → 동아리 | `public_jjaek`인 개인 원문 | active 목적지 동아리에서 현재 작성 가능 | 허용, 목적지 동아리의 새 인용 게시물 생성 |
| 개인 → 동아리 | `book_friends`·`private_jjaek` 개인 원문 | 어떤 동아리든 | 금지 |
| C. 동아리 → 같은 동아리 | 공개·승인·비공개 동아리의 원문 | 같은 active 동아리에서 현재 읽기·작성 가능 | 허용, 같은 동아리의 새 인용 게시물 생성 |
| 동아리 A → 동아리 B | 모든 동아리 원문 | 다른 동아리 | 금지 |
| 다시짹 → 개인/동아리 | A·B·C로 생성된 모든 다시짹 | 모든 목적지 | 금지 |

`active` 동아리라도 운영 정지 중이거나 공유자의 membership 활동이 정지되어 현재 작성할 수 없다면 B·C를 만들 수 없다. 공개 동아리의 비회원은 원문을 읽을 수 있어도 C를 작성할 수 없다. 승인·비공개 동아리의 비회원·초대 대기자는 원문 읽기와 C 작성 모두 할 수 없다. A의 active 공개 동아리 원문을 개인으로 다시짹하는 기존 동작은 유지한다.

## 3. 개인·동아리 및 원문 접근 경계

- B는 **개인 원문**만 대상으로 한다. `public_jjaek`이라는 저장값만 보고 동아리 글을 개인 원문으로 취급하지 않는다. 개인 원문의 visibility가 나중에 좁아지거나 현재 열람 권한이 사라지면 기존 B 게시물에서도 원문을 우회해 볼 수 없어야 한다.
- C는 원문과 목적지의 `group_id`가 같아야 한다. 원문 동아리가 공개인지와 무관하게 해당 동아리의 현재 read·write policy를 모두 통과해야 한다.
- 새 동아리 게시물의 독자는 목적지 Group 정책으로 결정된다. 인용 카드의 원문은 그 독자가 **원문도 읽을 수 있을 때만** 표시한다. 살아 있는 원문을 읽을 수 없는 경우 게시물 전체를 일반 조회에서 비노출하고 관계를 유지한다. 원문을 복사한 카드나 별도 목록·프로필·알림으로 이 경계를 우회하지 않는다.
- 프로필·동아리 목록·다시짹 목록·직접 URL은 현재 Group 조회 권한을 따른다. 홈에는 Group 게시물을 포함하지 않으며, 가입한 동아리의 통합 활동 피드는 `/groups`에서 제공한다. 피드 경계의 canonical 기준은 `docs/specs/group_activity_feed.md`다. 일반 팔로워에게 동아리 게시물을 자동 배포하지 않는다.
- 시스템 관리자의 운영 조사 권한은 일반 사용자 피드나 알림 수신자의 읽기 권한을 넓히지 않는다.

## 4. 동일 원문 재공유와 중첩 금지

동일 사용자는 동일 원문을 개인 공간에는 기존처럼 최대 한 번 다시짹할 수 있다. B·C에서는 **동일 사용자·동일 원문·동일 목적지 동아리** 조합을 최대 한 번만 허용한다. B의 개인 원문은 서로 다른 동아리에 각각 공유할 수 있으며, 개인 다시짹 1개와 동아리별 공유는 서로 독립적으로 센다. C는 같은 동아리 밖으로 공유할 수 없다.

중복 검사는 버튼 표시뿐 아니라 GET/POST 권한, 모델 검증, DB 제약에서 일치해야 한다. 동시 POST에서도 목적지별 중복은 생성되지 않아야 한다. 원문의 `requote?`가 참이면 다른 목적지로 바꾸거나 새 URL을 직접 호출해도 공유할 수 없다. 따라서 A로 만든 개인 다시짹을 B의 개인 원문처럼 동아리 B에 넣는 우회 경로도 없다.

## 5. 원문 수정·삭제·숨김·복구 lifecycle

| 원문 상태 변화 | A: 개인 다시짹 | B·C: 동아리 인용 게시물 |
| --- | --- | --- |
| 본문·책 문맥 수정 | 살아 있는 원문을 참조해 최신 내용 표시 | 같은 방식으로 현재 원문 표시. 원문의 과거 본문·책 snapshot을 만들지 않음 |
| visibility 축소·원문 접근 상실 | 기존 row를 유지하고 현재 원문 접근 권한이 없는 독자에게 비노출 | 기존 row와 독립 토론을 유지하되 살아 있는 원문 접근 권한이 없는 독자에게 비노출. 권한 회복 시 재판단 |
| 운영자 숨김 | 기존 원문·다시짹 관계와 감사 이력 보존, 일반 조회에서 비노출 | 기존 원문·인용 관계 및 독립 댓글·좋아요 보존, 일반 조회에서 비노출. 인용 게시물로 숨김 원문을 노출하지 않음 |
| 운영자 복구 | 현재 읽기 권한을 다시 검사해 노출 | 같은 방식으로 목적지와 원문 접근 권한을 다시 검사해 노출 |
| 작성자 삭제 또는 댓글 보존 tombstone | 기존대로 원문 참조를 끊고 작성자 전용 `private_jjaek`으로 전환 | 원문 참조를 끊고 **동아리 인용 작성자의 의견과 독립 댓글·좋아요를 목적지 동아리에서 유지**. 원문 카드 대신 삭제 사실만 표시 |

B·C의 원문 삭제 안내에는 삭제 사실만 표시한다. 원문 본문, 책 제목·메타데이터, avatar, 작성자 표시 이름 등 원문 식별 정보는 새 snapshot으로 저장하거나 화면에 재노출하지 않는다. 기존 원문을 열 수 있는 링크도 제공하지 않는다. 기존 개인 다시짹 A의 삭제 안내와 작성자 전용 정책은 그대로 둔다.

삭제된 원문은 더 이상 조회할 수 없으므로 B·C의 독자에게 원문 접근을 재요구하지 않는다. 대신 **현재 목적지 동아리 접근 권한**과 인용 게시물 자신의 숨김·삭제 상태를 검사한다. 원문 삭제 사건을 설명하는 최소 marker(기존 `quoted_source_deleted_at` 활용 가능)를 남기고, 새 동아리 글의 본문·댓글·좋아요와 기존 moderation 이력은 삭제하지 않는다. 살아 있는 원문의 숨김을 삭제처럼 취급해 이 예외를 적용해서는 안 된다.

동아리가 inactive가 되면 기존 active member의 과거 글 읽기 규칙을 유지하고 B·C 새 작성은 금지한다. 운영 정지 중에도 기존 read boundary는 유지하되 새 동아리 작성은 금지한다. 공유 작성자가 동아리에서 탈퇴·내보내기·활동 정지되더라도 기존 글과 댓글·좋아요를 자동 삭제하지 않는다. 새 작성·수정·상호작용 및 기존 글 조회는 각각 현재 membership, Group, Jjaek 정책에 따른다. 인용 게시물 자체가 숨겨지거나 삭제될 때도 일반 동아리 Jjaek의 moderation 및 작성자 lifecycle을 따른다.

## 6. 독립적인 본문·댓글·좋아요

B·C에서 새 게시물의 `content`는 공유 작성자가 직접 작성한 의견이며 필수다. 일반 짹·책짹 원문 모두 인용할 수 있다. 목적지의 새 게시물을 책짹으로 작성한다면 기존 책 선택·서재 보유 규칙을 별도로 만족해야 하며, 원문의 `book_id`를 자동 복사하지 않는다. 인용 카드는 살아 있는 원문을 현재 시점에 참조해 보여준다.

원문 댓글과 좋아요는 원문에 남는다. 공유 게시물에는 별개의 댓글과 좋아요가 연결된다. 동아리 댓글은 새 게시물의 Group 접근 범위를 상속하고 기존 Group 댓글 작성·수정 정책을 따른다. 원문 작성자는 새 동아리 게시물의 댓글을 원문 댓글처럼 관리하거나 열람할 권한을 자동으로 얻지 않는다. 원문 삭제 뒤에도 B·C 게시물이 목적지 권한에 따라 보이는 동안 그 게시물의 독립 토론을 계속할 수 있다.

## 7. Notification과 조회 보안

- A의 기존 다시짹 알림을 유지한다. B·C가 성공적으로 생성되면 원문 작성자에게 기존 `requote_created` 성격의 알림을 한 번 보낸다. 알림 문구도 다시짹으로 통일하고 현재 읽을 수 있는 경우에만 개인 피드·목적지 동아리·같은 동아리 내부를 구분한다. 자신이 자신의 원문을 인용했을 때는 알리지 않는다. 알림 생성 시 수신자가 새 게시물과 살아 있는 원문을 읽을 수 있어야 한다. 비공개 동아리 원문의 작성자가 이미 membership을 잃었다면 알리지 않는다.
- B·C 게시물에 달린 새 댓글은 **새 게시물 작성자**에게 기존 `comment_created` 정책대로 알린다. 원문 작성자는 그 이유만으로 새 댓글 알림을 받지 않는다. 자기 댓글·중복 알림의 기존 억제 규칙을 유지한다.
- 알림 row는 시간이 지나도 남을 수 있다. 알림 목록의 문구에는 비공개 원문 본문·책 정보·동아리 이름 등 현재 권한 없이 읽을 수 없는 정보를 넣지 않는다. 클릭 시 수신자의 현재 Jjaek/Group policy와 원문 가시성을 다시 확인하고 접근할 수 없으면 안전한 화면으로 보낸다. 알림 자체는 접근 권한이 아니다.
- 인용 카드, 다시짹 수·목록, 프로필, 홈, 댓글 링크와 직접 URL 모두 현재 원문·목적지 경계를 적용한다. 숨김 원문이나 접근할 수 없는 비공개 동아리 원문이 HTML·Turbo 응답 또는 알림에서 새어 나오지 않아야 한다.

## 8. 사용자 UI와 작업 동선

- A는 기존 개인 작성 동선의 **내 피드에 다시짹** 버튼과 작성 화면을 사용한다.
- B는 읽을 수 있는 전체 공개 개인 원문에서 **동아리에 다시짹**을 시작한다. 현재 작성 가능한 동아리만 목적지로 선택하고, 원문 인용 카드와 의견 입력을 확인한 뒤 동아리 게시물을 만든다.
- C는 동아리 원문에서 **이 동아리에 다시짹**을 시작한다. 목적지는 같은 동아리로 고정하고 의견을 입력한다. 새 글은 동아리 피드에서 원문과 구분되는 인용 카드·목적지 문맥을 보여준다.
- 버튼은 원문 권한과 목적지 작성 권한, 목적지별 중복 여부를 반영한다. GET 작성 화면과 POST 생성도 동일한 정책을 다시 검사한다. 원문 ID·목적지 ID를 바꾼 요청, 이전에 열어 둔 작성 화면, 중복 제출에 대한 서버 검증이 필요하다.
- 세 경로의 카드 헤더·작성 화면·알림은 모두 다시짹으로 표현하면서 출발·도착 문맥을 구분한다. 새 문구는 `ko`·`en` locale에 함께 정의하는 것을 구현 기준으로 삼는다. 목적지 Group의 visibility를 개인 visibility 선택 UI로 표시하지 않는다. 일반 독자의 다시짹 개수와 목록에는 현재 읽을 수 있는 A·B·C 게시물만 포함한다. 원문 작성자는 읽을 수 없는 동아리 다시짹도 숨김·삭제되지 않고 원문과 연결된 유효 게시물이라면 개수에 포함하며, 목록에는 제한 카드로 표시한다. 승인 동아리처럼 현재 공개 조회가 허용된 경우에만 작성자·원문 종류·동아리 이름을 표시하고, 비공개·비활성 동아리는 식별 정보를 익명화한다. 제한 카드에는 의견·댓글·좋아요·게시물 링크를 표시하지 않는다. 목록 조회 권한은 새 다시짹 작성 권한과 분리한다.

## 9. 현재 구현 상태

- A·B·C는 기존 `Jjaek`, `quoted_jjaek`, optional `group_id` 구조로 구현되어 있다.
- 모델 검증과 DB 제약은 개인 공간과 목적지 동아리별 중복을 구분하며, 중첩 다시짹과 동아리 간 직접 공유를 막는다.
- `JjaekPolicy`와 각 scope는 공유 경로의 원문·목적지 권한을 함께 검사한다. 홈 `FeedScope`는 모든 Group 게시물을 제외하며, `/groups`의 `GroupActivityScope`는 현재 동아리 읽기 권한 안에서 활동을 조회한다. 이는 `docs/specs/group_activity_feed.md`의 피드 경계와 일치한다.
- 원문 삭제 처리는 A와 B·C를 분기한다. A는 작성자 전용 개인 콘텐츠로 전환하고, B·C는 원문 식별 정보를 제거한 뒤 목적지 동아리의 독립 본문·댓글·좋아요를 보존한다.
- A·B·C 작성 화면, 카드 문맥, 알림과 locale이 구현되어 있다. 다시짹 목록과 count의 노출 기준은 `requotes_mvp.md`가 담당한다.
- 원문 숨김·복구와 원문 삭제는 기존 `ModerationAction` 이력을 소급 변경하지 않는다.

## 10. Acceptance criteria와 RSpec 검증 항목

1. A: active 공개 동아리 원문은 개인 다시짹 가능하고 승인·비공개·inactive 원문은 금지된다. 기존 개인 원문 → 개인 다시짹의 생성·조회와 원문 삭제 후 작성자 전용 전환도 유지된다.
2. B: 전체 공개 개인 짹·책짹을 작성 가능한 동아리에 공유할 수 있다. 책친구 공개·나만 보기 원문과 작성 권한 없는 목적지는 GET/POST 및 직접 요청에서 거부된다.
3. C: 공개·승인·비공개 동아리에서 현재 읽기·작성 권한이 있는 사용자는 같은 동아리 원문을 의견과 함께 인용할 수 있다. 비회원·활동 정지 회원·운영 정지 동아리의 신규 작성은 거부된다.
4. 동일 사용자의 동일 원문은 개인 1회, 각 동아리 1회만 허용한다. 서로 다른 동아리 공유는 허용한다. 동시 중복 요청에서도 DB가 목적지별 유일성을 지킨다.
5. 다른 동아리 원문, 이미 다시짹된 원문, A를 거쳐 동아리로 들어오는 원문은 버튼·GET·POST·모델 수준에서 거부된다.
6. 원문 수정은 최신 카드로 반영된다. visibility 축소·접근 상실·운영자 숨김 동안 B·C 게시물에서 원문이 유출되지 않고, 복구 후 현재 권한으로 다시 보인다.
7. 원문 hard delete와 tombstone 후 A는 기존대로 작성자 전용이 되고 B·C는 목적지 동아리에서 의견·댓글·좋아요를 유지한다. B·C에는 삭제 사실만 표시하고 원문 본문·책 정보·작성자 snapshot을 노출하지 않는다. 기존 moderation 이력은 보존된다.
8. B·C의 댓글·좋아요는 원문과 독립적이다. 탈퇴·활동 정지·동아리 inactive/suspended 이후 읽기와 새 상호작용은 각각 현재 정책을 따른다.
9. 원문 작성자 알림과 새 게시물 댓글 알림은 각각 허용된 대상에게만 생성된다. 비공개 동아리 접근 상실 후 알림 문구·링크·직접 URL은 원문과 동아리 정보를 유출하지 않는다.
10. 동아리 게시물은 해당 동아리의 접근 권한 범위와 권한 있는 프로필에서만 보이고 일반 팔로워에게 자동 배포되지 않는다. 홈 피드에서는 모든 Group 게시물을 제외하고 `/groups`에서 가입한 동아리의 통합 활동 피드를 제공한다. 피드 경계는 `docs/specs/group_activity_feed.md`를 따른다.

회귀 검증은 기존 `jjaek` 모델·정책·request·notification spec에서 권한 매트릭스, 직접 URL/파라미터 조작, DB 중복 및 동시성, 원문 lifecycle, 댓글·알림 경계를 다룬다. 중복 예제를 늘리지 않고 기존 A 회귀 사례를 유지한다.

## 11. 유지보수 경계

2~8절의 A·B·C 허용 범위, 목적지별 1회 제한, 중첩·동아리 간 공유 금지, 원문 삭제 후 B·C 토론 보존과 A의 작성자 전용 전환은 확정된 제품 정책이다. 후속 변경은 이 경계를 모델·DB 제약, Pundit policy/scope, 직접 요청, 알림과 화면 노출에서 함께 유지해야 한다. 구현 구조의 현재 요약은 `../architecture/current_system.md`를 따른다.
