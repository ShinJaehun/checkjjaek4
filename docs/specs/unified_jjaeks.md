# 통합 짹

## 문서 상태와 범위

통합 짹과 cleanup 1·2단계를 반영한 현재 canonical spec이다. 과거의 일반 짹·책짹·추천짹
유형별 작성·조회 설명과 충돌하는 부분은 이 문서를 우선한다. 과거 추천짹 정책은
[역사적 명세](book_recommendation_jjaeks.md)에 보존한다. Group·moderation·다시짹의
권한 정책은 각 canonical spec을 유지한다.

개발 DB 전환과 사용자 검증은 완료되었으며 운영 배포·DB 전환은 아직 수행하지 않았다.
운영 전환·복구의 실행 기준은 [OCI 운영 문서](../ops/deploy_oci.md)를 따른다.

## 1. 통합 콘텐츠와 책 첨부

- 기존 일반 짹·책짹·추천짹을 하나의 `Jjaek` 작성·수정·표시 체계로 통합한다. 기본 명칭은 `짹`이다.
  첨부 책의 유무나 권수로 독후감·추천글 등 별도의 게시물 유형이나 추천 의미를 추론하지 않는다.
- 하나의 짹에 책을 선택적으로 0~5권 첨부한다. 0권도 정상이며 책만 있고 본문이 없는 게시물은 허용하지 않는다.
  기존 필수 본문 검증, 새 본문의 최대 200자와 문자 계산 기준, 해시태그 처리를 유지한다.
- 같은 책은 한 짹에서 한 번만 첨부하며 기존 추천 목록의 선택 순서를 보존하며 별도 순서 변경 UI는 제공하지 않는다.
  서버에서도 중복·권수·책 참조를 검증하고 5권 초과나 유효하지 않은 참조는 부분 저장 없이 거부한다.
- 첨부 유무는 콘텐츠의 속성이다. 사용자·동아리 문맥, 공개 범위, 숨김·삭제 상태, 다시짹 여부와 분리한다.
  관리자 콘텐츠 배지는 `짹 / 동아리짹 / 다시짹 / 댓글` 중 하나다. 다시짹도 기존 `Jjaek`의 인용 관계로 유지한다.
- 첨부 책은 그 짹 자신의 연결이다. 다시짹의 원문에 붙은 책을 새 짹의 첨부로 복사하거나 중복 집계하지 않는다.
  친구 프로필의 두 사람 전용 대화에도 책 0~5권을 첨부할 수 있다. 새 다시짹의 책 첨부와 기존 다시짹의
  새로운 책 추가는 금지한다. 과거 다시짹에 연결된 책은 보존한다.

## 2. 서재와 첨부의 독립성

- 공용 도서 정보는 `Book`, 개인 책장 소속·독서 상태·스티커는 기존 서재 모델,
  짹의 책 첨부는 Jjaek과 Book의 연결이 각각 책임진다. 첨부를 BookshelfEntry의 소유 관계로 표현하지 않는다.
- 내 서재에 없는 책도 짹에 첨부할 수 있다. 서재 등록을 첨부나 일반 짹 게시의 선행 조건으로 두지 않는다.
- 첨부의 선택·게시·수정·제거는 BookshelfEntry나 BookActivity를 생성·이동·삭제하지 않는다.
  서재 등록은 사용자의 별도 명시적 동작이며 기존 등록·중복·책장 선택 정책을 따른다.
- 서재에서 책을 제거하거나 책장을 이동해도 짹과 첨부는 유지한다. 짹에서 첨부를 제거해도 서재는 유지한다.
  공용 Book을 개인 서재나 첨부 제거의 부수 효과로 삭제하지 않는다.
- 짹과 첨부 책 정보의 열람은 그 짹의 현재 권한을 따른다. 첨부로 비공개 책장 소속이나 독서 상태·스티커가
  공개되지 않으며, 기존 서재 정보의 열람 권한은 별도로 적용한다.
- 도서 검색·임시 선택 단계는 DB에 초안·Book·첨부를 생성하지 않는다. 기존 추천짹의 사용자 바인딩 임시 참조,
  만료·위변조 검사, 기존 Book 재사용과 메타데이터 덮어쓰기 금지 원칙을 통합 첨부에서도 유지한다.
  필요한 신규 Book·본문·첨부는 최종 저장에서 함께 성공하거나 롤백되어야 한다.

## 3. 작성 UI와 공개 권한

모든 작성 위치에서 일반 짹·책짹·추천짹의 유형 선택을 본문과 선택적 책 첨부로 통합한다.
검색·선택·제거·화면 이동 및 저장 실패 때 본문·첨부 순서·작성 문맥을 보존하고,
취소한 작성 상태가 다음 작성에 섞이지 않게 한다. 작성은 인라인 Rails form으로 유지하며, 책 검색·선택은 기존 플로팅 창과 페이지 결과를 사용한다(7절).
UI 용어는 ko·en locale에 함께 반영한다.

| 진입 위치 | 작성 문맥과 UI | 공개 권한 |
| --- | --- | --- |
| 홈 | 개인 짹 본문과 책 0~5권 첨부. 기존 유형 선택을 통합 | 기존 전체 공개·책친구 공개·나만 보기 선택 및 기본값 유지 |
| 자기 프로필 | 현재처럼 일반 작성은 홈에서 진행. 프로필의 표시에는 통합 체계 적용 | 자기 프로필이라는 이유로 다른 게시물의 읽기 권한을 넓히지 않음 |
| accepted 책친구의 타인 프로필 | 대상자를 고정한 두 사람 전용 대화에 책 0~5권 첨부 가능. 공개 범위 대신 전용 안내 표시 | 아래 대화 정책을 본문과 첨부 책 정보에 동일하게 적용 |
| 동아리 | 해당 동아리 문맥의 통합 작성. 일반 짹·동아리 책짹·추천짹 유형 분리 제거 | 개인 공개 범위 UI를 제공하지 않고 현재 Group 작성·읽기 정책 적용 |

- 홈 개인 피드에는 동아리 게시물을 편입하지 않는다. 가입 동아리 활동은 기존 `/groups`에서 제공하며,
  작성자 프로필에 표시할 때도 현재 독자의 동아리 열람 권한을 검사한다.
- 공개 동아리 비회원의 읽기 가능 여부와 승인·비공개 동아리의 현재 회원 경계,
  lifecycle·운영 정지·회원 활동 정지에 따른 쓰기 제한을 보존한다. 첨부로 이 경계를 우회하지 않는다.
- 단건은 Pundit policy, 목록은 scope에서 제한한다. 관리자 운영 조사 권한을 일반 검색·발견 권한으로 확장하지 않는다.
  HTML과 Turbo 요청은 같은 인가·검증·저장 결과를 보장한다.
- 책 상세에서도 서재 등록과 첨부 작성은 독립적이다. 미등록 책에도 작성할 수 있다.
  책 상세의 첨부 기본 선택·다른 책 추가·제거와 작성 완료 후 초기화는 7절을 따른다.

### 프로필 대화의 두 사람 전용 정책

`social_relationships_mvp.md`의 확정 정책을 통합 후에도 우선 적용한다.

- `target_user_id`가 있고 작성자와 대상자가 다르면 저장된 visibility와 첨부 유무보다 두 사람 전용 권한이 우선한다.
  제3자는 모두와 책친구여도 읽을 수 없다. self-target는 기존처럼 일반 짹으로 취급한다.
- 신규 대화 작성은 현재 accepted 책친구에게만 허용한다. 관계 해제·Follow 변경은 과거 대화 읽기 권한을 없애지 않는다.
  공개 범위를 선택하지 않으며 조작된 visibility 요청도 대화를 공개로 바꾸지 못한다.
- 홈·프로필·직접 URL·책 상세·검색·태그·발견·알림·기존 인용에서 동일한 경계를 적용한다.
  기존 대화와 새 대화에 첨부된 책 표지·제목·건수 등 책 정보에도 같은 두 사람 전용 경계를 적용한다.
- 댓글·좋아요는 부모 접근 권한을 상속한다. 과거 제3자의 반응은 보존하고 자기 댓글 삭제·좋아요 철회만 허용한다.
  최소 정리 화면에서 대화 본문·상대 정보·다른 댓글을 노출하지 않는다.
- 새 개인 다시짹·동아리 공유는 금지한다. 기존 인용 관계는 보존하되 살아 있는 원문 접근 권한을 재검사한다.
  대화 댓글은 대화 상대에게 알리고 자기 알림은 만들지 않는다.
- 일반 이용자 간 두 사람 전용 정책과 기존 시스템 관리자 조사·moderation 권한을 구분한다.
  통합을 이유로 visibility 일괄 변경이나 과거 반응·인용 데이터 정리를 수행하지 않는다.

## 4. 공통 카드와 발견

### 첨부 표시

- 책이 없으면 책 영역을 만들지 않는다. 첨부가 있으면 선택 순서대로 책 표지를 겹쳐 표시하고 제목 목록을 함께 제공한다.
  한 권은 단일 표지·제목, 여러 권은 겹친 표지와 각 책을 식별할 수 있는 전체 제목 목록으로 표시한다.
- 제목 목록은 첨부된 1~5권을 빠짐없이 순서대로 표시하며 각 책의 기존 상세 링크를 제공한다.
  겹친 표지만으로 책을 구분하도록 하지 않는다. 표지 누락 시에도 제목과 링크를 유지한다.
- 이 표현은 통합 짹 공통 카드에 적용하되 발견의 게시물 미리보기는 아래 요약 규칙을 적용한다. 책 한 권을 소개하는 발견의 대표 영역은
  대표 책의 정보와 해당 짹의 여러 첨부를 구분한다. 원문의 첨부와 다시짹 자신의 첨부도 구분한다.
- 읽을 수 없는 짹이나 원문, 숨김 안내와 인용 원문 삭제 안내에는 책 표지·제목·링크가 새어 나오지 않아야 한다.
  기존 책짹 자체의 댓글 보존 tombstone은 원래 조회 권한 안에서 기존 책 정보를 유지한다.
  첨부를 제거한 뒤 과거 책 연결을 fallback으로 복원하지 않는다.
  책 상세의 책친구 활동·타임라인에도 표지와 책 정보를 표시한다. 같은 책이라는 이유로 일괄 생략하지 않는다.

### 발견 후보 분류

발견 페이지는 책 첨부 여부에 따라 기존 두 영역을 유지한다.

| 분류 | 통합 후 기준 |
| --- | --- |
| 책이 첨부된 짹 | 짹 자신의 유효한 첨부가 1~5권인 원본. 과거 책짹과 추천짹 모두 포함 |
| 책이 없는 짹 | 짹 자신의 첨부가 0권인 원본 |

- 여러 책을 첨부한 짹은 첨부 순서대로 표지를 최대 3권 겹쳐 표시한다. 표지 오른쪽에는 같은 순서의 책 제목을
  최대 3권까지 한 권당 한 줄씩 표시하며 긴 제목은 말줄임표로 처리한다.
  4권 이상이면 나머지를 `외 N권`으로 요약한다. N은 전체 첨부 권수에서 표시한 3권을 뺀 값으로,
  4권은 `외 1권`, 5권은 `외 2권`이다. 한 권은 단일 표지와 제목을 표시한다.
- `book_id` 또는 `recommendation` 분기로 후보를 나누지 않는다. 한 짹이 여러 책에 연결되어도 같은 영역에서
  중복 카드나 건수로 계산하지 않는다. 주요 책 후보는 첨부된 각 책을 기준으로 삼고 해당 책의 짹을 중복 없이 모은다.
- 기존 주요 책 1권·관련 짹 최대 3개, 책 없는 짹 최대 3개와 추천 서재·동아리 구성을 유지한다.
  두 분류 모두 개인 영역의 현재 접근 가능한 전체 공개·숨김/삭제 아님·원본이라는 조건을 적용한다.
  두 사람 전용 대화·다시짹·삭제 원문 잔존 레코드는 공개 발견 후보에 넣지 않는다.
- 일일 발행·Asia/Seoul 날짜·다음 날부터 신규 짹 포함·결정적 선정·후보 부족 처리와
  매 요청 현재 권한 재검사 정책을 유지한다. 추천 동아리 최근 글도 첨부 유무에 맞춰 표시하되 기존 Group scope를 지킨다.

## 5. 검색과 관리자 모니터링

관리자 모니터링의 콘텐츠 유형을 다음과 같이 통합한다. 이 분류는 일반 통합 검색에 댓글 검색을 추가한다는 뜻이 아니다.

| 관리자 콘텐츠 기본 유형 | 분류 기준 |
| --- | --- |
| 짹 | `group_id`가 없는 일반 Jjaek. 다시짹 제외, 첨부·과거 종류와 무관 |
| 동아리짹 | `group_id`가 있는 일반 Jjaek. 다시짹 제외, 첨부·과거 종류와 무관 |
| 다시짹 | 개인·동아리 인용 Jjaek 및 원문 삭제 marker가 있는 다시짹 |
| 댓글 | Comment. 부모 짹의 유형·첨부 유무와 별개이며 읽기 권한은 부모를 따름 |

- 검색·관리자 모니터링에서 책짹·추천짹을 독립 콘텐츠 유형으로 분리하지 않는다.
  개인·동아리의 `영역`, 콘텐츠 `유형`, 숨김·삭제 `상태`는 서로 다른 축으로 유지한다.
  일반 검색의 탭·기존 URL 호환은 11절을 따른다. 별도 책 첨부 필터는 추가하지 않는다.
- 일반 문자열 검색은 짹·다시짹 자신의 본문을 조회하며 기존 댓글 검색 제외 정책을 유지한다.
  사용자·동아리 검색은 유지한다. 인용 원문 본문이나 삭제 snapshot을 검색·미리보기에 복제하지 않는다.
- 일반 검색에는 관리자 조사 예외를 추가하지 않는다. 관리자 모니터링의 댓글 조회·검색은 기존 조사 권한과
  부모 콘텐츠 및 본문 표시·검색 경계를 유지한다.
- 태그 검색도 책짹·추천짹 분리를 없애고 짹·다시짹의 현재 조회 경계와 태그 연결을 유지한다.
  일반 통합 검색의 댓글 제외는 태그 검색에서도 유지하며 댓글 태그 저장·검색은 이번 범위에 추가하지 않는다.
- 관리자 User 콘텐츠의 flat 목록과 Group 콘텐츠의 thread 목록은 기존 단위를 유지한다.
  유형 필터를 통합하더라도 Group은 일치한 row가 속한 전체 thread를 표시하며 건수·페이지 단위를 row로 바꾸지 않는다.
- 시스템 관리자와 동아리 관리자의 권한·숨김 authority 경계 및 감사 이력을 유지한다.
  특히 동아리 콘텐츠 관리의 platform-hidden·삭제 본문 표시/검색 금지를 통합 분류로 완화하지 않는다.
  서비스 전체 전역 inventory를 새로 도입하지 않는다.

## 6. 최종 데이터 모델과 운영 전환

- `Jjaek`은 본문·게시 문맥·visibility·인용·삭제 상태를 관리한다.
  `JjaekBookAttachment`(`jjaek_book_attachments`)가 Book과의 연결과 position을 관리하며
  `attached_books`가 유일한 책 조회 association이다. 외래키, 짹별 Book·position 유일성,
  position >= 0 제약과 모델의 최대 5권 검증을 유지한다.
- `Jjaek.book_id`, `recommendation`, `book_attachments_migrated`는 제거했다.
  `content_kind`, `recommended_books`와 구형 유형별 scope·저장 wrapper도 사용하지 않는다.
  현재 게시물 유형을 과거 분류에서 추론하지 않는다.
- `legacy_source_kind`는 과거 원문의 삭제 snapshot(book/recommendation)을 위한 선택적 역사 정보다.
  신규 글은 nil이며 삭제 snapshot 종류는 general이다. 기존 `quoted_source_kind` 등 snapshot은 보존한다.
  과거 단일 책 원본의 첨부를 명시적으로 교체해 기존 표시 연결이 없어지면 book marker도 해제한다.
- 첨부의 `visible_on_tombstone`은 기본 false다. 전환 직전 단일 book_id와 일치한 연결만 true로 기록한다.
  댓글을 남기는 tombstone은 기존 단일 책 정보만 원래 읽기 권한 안에서 표시한다.
  통합 이후 첨부는 삭제 후 새로 노출하지 않으며 다시짹 tombstone에는 책을 표시하지 않는다.
  본문·숨김·Group·프로필 대화의 권한 경계는 삭제 후에도 유지한다.
- 개인 다시짹 A는 원문 삭제 시 연결을 끊고 private로 전환하며 기존 작성자·종류·삭제 시각 snapshot을 보존한다.
  화면은 작성자와 통합 명칭의 삭제 안내를 사용하며 과거 종류를 현재 유형으로 복원하지 않는다.
  동아리 B/C는 원문 연결·작성자·종류 등 식별 정보를 제거하고 목적지의 독립 본문·댓글·좋아요를 보존한다.
  상세 정책은 [group_sharing_requotes.md](group_sharing_requotes.md),
  [requotes_mvp.md](requotes_mvp.md)를 따른다. 살아 있는 원문은 현재 읽기 권한을 재검사한다.

### 기존 DB와 빈 DB의 migration 순서

기존 migration 파일은 수정하거나 삭제하지 않는다. 빈 DB도 같은 migration 이력과 최종 schema로 수렴해야 한다.

| 순서 | migration | 역할 |
| --- | --- | --- |
| 1 | `20261103000000_add_recommendations_to_jjaeks` | 당시 추천 연결 생성. 운영에 연결 테이블이 없어도 먼저 생성 |
| 2 | `20261106000000_generalize_jjaek_book_attachments` | 단일 book_id 백필·전환 flag. 혼합 충돌·5권 초과 시 중단 |
| 3 | `20261107000000_rename_jjaek_recommendations_to_book_attachments` | 기존 연결 테이블·인덱스·position CHECK 명칭 변경 |
| 4 | `20261108000000_remove_legacy_jjaek_book_columns` | 전환 누락 검사 후 역사 정보 분리와 구형 세 컬럼 제거 |

- 같은 Jjaek·첨부 row를 유지한다. 기존 Jjaek/첨부/Book ID·position·작성/수정 시각,
  댓글·좋아요·태그·알림·moderation과 인용 관계를 새로 만들거나 재작성하지 않는다.
  서재 등록·BookActivity·새 알림을 생성하지 않으며 기존 본문을 자르거나 visibility를 넓히지 않는다.
- 전환 전 혼합 연결·중복·5권 초과·끊긴 외래키를 확인한다. 충돌을 임의 병합·삭제하지 않는다.
  백필과 컬럼 제거는 잠금을 사용하므로 웹·내장 작업 등 모든 쓰기를 중단하고 수행한다.
- 백필과 컬럼 제거는 down으로 복원할 수 없다. rename의 이름 복원만으로 구버전 호환이 회복되지 않는다.
  네 DB의 배포 직전 백업과 호환 이미지로 함께 복구해야 한다. 덤프를 기존 DB에 `pg_restore --clean`으로
  덮는 방식은 새 객체를 남길 수 있으므로 빈 DB 재생성·복원과 실제 복구 리허설이 필요하다.
- 과거 migration spec은 격리 schema와 익명 SQL record를 사용한다. 현재 모델에 삭제된 컬럼을 설정하지 않는다.
  flag 변경은 의도된 전환이며 불변 비교에서 제외하되 관계·ID·시각·첨부 보존 검증은 유지한다.

## 7. 공통 폼·책 상세 초기화·첨부 카드

- 공통 작성·수정 폼은 동일한 최대 폭과 스타일을 사용한다. 책 추가는 우측 상단, 제출은 본문·첨부 목록 아래 우측에 둔다.
  첨부 목록에는 작은 표지·제목·저자와 기존 제거·서재 등록 동작을 표시하고, 최대 5권일 때 목록 내부 스크롤을 유지한다.
  공개 범위 SVG 카드는 유지하며 프로필 대화·동아리에는 표시하지 않는다.
- textarea placeholder는 홈 `내 소식에 남길...`, 동아리 `[동아리 이름]에 남길...`,
  프로필 `[프로필 사용자 이름]님에게 남길...`, 책 상세 `이 책에 남길...`로 표시한다.
  책 상세 문맥에서는 동아리에서 진입했더라도 책 상세 placeholder를 사용한다. 수정 권한·공개 범위는 바꾸지 않는다.
- 타인 프로필 작성 폼의 대화 안내는 `이 짹과 댓글은 작성자와 %{name}만 볼 수 있습니다.`로 표시한다.
  현재 대상 프로필의 실제 이름을 ko/en locale에 보간하고 HTML escaping을 유지한다.
  본인 프로필에는 적용하지 않으며 기존 두 사람 전용 읽기 권한은 유지한다.
- 동아리 작성·수정은 게시물의 실제 `group`을 기준으로 분기한다. 일반 동아리 폼의 단순 대상 동아리 안내는 제거한다.
  프로필 대화 안내와 같은 작은 보조 문구 스타일로 공개 동아리는 `이 짹과 댓글은 로그인한 누구나 볼 수 있습니다.`,
  승인·비공개 동아리는 `이 짹과 댓글은 동아리 회원만 볼 수 있습니다.`를 작성·수정·검증 실패 화면에 일관되게 표시한다.
  동아리 이름은 placeholder에 표시하고 안내에서는 반복하지 않는다. 실제 읽기·쓰기 권한과 가입 정책은 변경하지 않는다.
  동아리 인용 공유의 목적지 선택은 별개로 유지하며 기존 visibility 값·인가·저장 계약은 변경하지 않는다.
- 책 상세 새 폼은 현재 책 1권과 빈 본문으로 시작한다. 기본 첨부 제거로 0권 작성, 다른 책 추가로 최대 5권 작성을 허용한다.
  선택 작업 중에는 기존 Turbo permanent DOM으로 본문·visibility·첨부 순서를 보존한다.
- 책 선택창을 열 때 원래 폼의 첨부 영역을 DOM snapshot으로 보관한다. 추가·제거는 선택 완료 전까지 임시 변경이다.
  선택 완료는 현재 목록을 확정하고, 닫기·선택 검색 페이지의 돌아가기·브라우저 뒤로 원래 화면 복귀는 snapshot을 복원한다.
  본문·공개 범위·동아리·프로필 문맥은 변경하지 않는다. 재개방 시 직전 확정 목록을 새로운 취소 기준으로 사용한다.
  원래 폼은 검색·책 상세 이동 동안 보존하며 책 미리보기의 별도 작성 폼은 선택 작업 중 숨긴다.
  종료 중에는 이전 revision의 응답과 Stream을 적용하지 않아 취소·확정 목록이 뒤늦게 덮이지 않게 한다.
- 책 상세 폼의 `book_context_id`(기존 Book)와 `book_context_token`(외부 검색 책)은 성공·실패 응답의 책 페이지 문맥에만 사용한다. 실제 첨부는 `selected_books[]`,
  동아리 문맥은 기존 경로·게시물과 서버 권한 검사로 결정한다. 책 문맥 입력으로 첨부나 게시 대상을 변경하지 않는다.
  게시 성공 후 실제 저장된 첨부에 현재 책이 포함되면 현재 책 상세로 돌아가 빈 본문·현재 책 1권의 새 폼을 표시한다.
  현재 책을 제거하고 다른 책만 첨부했거나 0권으로 게시하면 홈(`/`)으로 이동한다. 동아리 책 상세에서도 게시 대상은 그대로 유지한다.
  이동은 검증된 책 문맥과 저장된 첨부를 기준으로 결정하며 클라이언트의 임의 이동 경로를 신뢰하지 않는다.
  일반 홈·동아리·프로필 작성과 다시짹의 기존 이동 정책은 유지한다.
  검증 실패는 입력한 본문·공개 범위·첨부 순서와 제거 상태를 유지한다.
  새 방문에는 과거 초안을 복원하지 않도록 책 상세의 Turbo snapshot 캐시를 사용하지 않는다. 선택 작업의 DOM 보존은 유지한다.
- 0권 카드는 책 영역을 만들지 않고, 1권은 기존 단일 표지·책 정보 스타일을 사용한다.
  표지는 최대 5권 모두 표시한다. 1~3권은 한 줄, 4권은 3+1, 5권은 3+2로 나누고 각 줄 안에서 일부 겹친다.
  선택 순서대로 모든 책의 제목·저자·상세 링크를 표시하며 모바일에서는 제목 영역을 표지 아래에 두어 폭을 확보한다.
  책 상세 타임라인·책친구 짹 미리보기에도 적용하며 기존 scope·숨김·삭제·인용 원문 보호와 미리보기의 독서 상태 생략은 유지한다.
- 지정된 화면의 책 표지는 공통 `books/thumbnail`의 세 규격으로 통일한다. 아래 크기는 너비 × 높이의 상한이며
  원본 비율을 유지하고 표지가 없는 책의 기본 표지도 같은 규격을 사용한다.

  | 규격 | 크기 | 적용 위치 |
  | --- | --- | --- |
  | `large` | 96 × 144px, `md` 이상 160 × 224px | 일반·첨부용 책 찾기 결과, 책 상세 상단 제목 카드 |
  | `medium` | 80 × 112px | 1권 첨부 짹과 인용 원문 카드 |
  | `small` | 56 × 80px | 2~5권 첨부 짹, 책 선택 모달의 선택 목록, 작성·수정 폼의 첨부 목록 |

  검색 결과 두 모드는 같은 반응형 대형 규격을 사용하고 모바일에서는 작은 대형 크기를 사용한다.
  여러 권의 기존 겹침·첨부 순서와 제목·버튼 배치는 유지한다. 발견 화면의 별도 크기는 변경하지 않는다.
- 일반·책 첨부·기존 추천 게시물과 인용 원문 카드의 헤더 명칭은 `짹`으로 통일한다.
  문장 안의 `동아리`는 기존 작은 중립 배지로 표시하며 작성자·원문 작성자·동아리 링크는 유지한다.
  배지는 게시 공간을 구분하며 콘텐츠 유형을 의미하지 않는다. 향후 교실 공간 표현과 구분할 수 있도록 이 의미를 유지한다.
  `책짹`·`추천짹` 유형 표현은 복원하지 않는다.
  책 제목·표지·저자는 본문에서 표시하고 헤더에 반복하지 않는다. 삭제된 원문 안내·기존 snapshot과 비공개 정보 보호는 유지한다.

브라우저에서는 작은 노트북에서 모달 열기/닫기/Escape·검색·페이지 이동 중 본문 보존과 5권 제한·개별 제거,
HTML/Turbo의 실패·재저장, 프로필 제3자 비노출과 동아리 권한 상실 후 저장 거부를 확인한다.

## 8. 책 상세의 서재 미등록·외부 검색 책 작성

- 서재 등록 여부와 관계없이 기존 Book 상세와 외부 검색 결과 상세에서 같은 공통 작성 폼을 제공한다.
  현재 책 1권을 기본 첨부하고 기존 공개 범위·책 추가/제거·최대 5권과 선택 완료/취소·Turbo 초안 보존을 유지한다.
  작성 권한은 기존 개인/동아리 Pundit 정책을 따르며 프로필 대화의 두 사람 전용 경계도 변경하지 않는다.
- 외부 검색 책의 단순 조회·임시 선택은 Book을 저장하지 않는다. 기존 사용자 바인딩 서명 토큰과
  30분 만료의 임시 참조를 재사용하고, 최종 게시에서 검증한 뒤 Book을 재사용하거나 생성한다.
  기존 Book 메타데이터를 덮어쓰지 않으며 위변조·만료·타 사용자 참조·중복·6권 이상은 부분 저장 없이 거부한다.
  본문 검증 실패도 새 Book·짹·첨부를 남기지 않는다.
- 기존 Book과 외부 검색 책을 섞어 첨부할 수 있고 선택 순서를 유지한다. 외부 책 상세의 작성 문맥도
  사용자 바인딩 서명 데이터로 확인하며, 저장된 첨부 결과에 따른 성공 이동·새 폼 초기화는 7절과 같다.
  현재 책을 제거하면 그 책을 새로 저장하지 않는다. 실패 화면에도 검증 가능한 책 문맥과 제출한 입력을 유지한다.
- 짹 작성만으로 BookshelfEntry·독서 상태·BookActivity를 생성하거나 변경하지 않는다.
  기존 서재에 담기는 별도 명시적 동작으로 유지한다. 게시된 짹은 실제 첨부된 책 상세 목록에서 기존 scope 안에 표시한다.

```bash
bundle exec rspec spec/system/book_posting_spec.rb spec/system/recommendation_editing_spec.rb
```

## 9. 통합 작성 UI 표현 보완

- 프로필 대화의 카드·상세 공개 범위는 로그인한 당사자를 기준으로 `%{name}님과 나만 보기`로 표시한다.
  작성자에게는 프로필 주인, 프로필 주인에게는 작성자 이름을 표시하며 영어도 같은 의미로 제공한다.
  관리자 조사 등 당사자가 아닌 열람 문맥에서는 `당사자만 보기`로 표시한다.
  실제 두 사람 전용 권한, 일반 짹의 공개 범위 명칭과 작성 폼의 구체적인 열람 대상 안내는 유지한다.
- 동아리에 다시짹할 대상은 기존 `group_id`의 필수 라디오 카드로 선택한다. 동아리 이름·유형과
  공개 동아리의 로그인 사용자 열람/승인·비공개 동아리의 회원 열람 범위를 표시한다.
  기존 선택 카드의 선택·키보드 포커스 스타일을 재사용하고 모바일 1열·넓은 화면 2열로 배치한다.
  검증 실패 시 선택을 유지하며 기존 작성 권한·이미 공유한 동아리 제외·인용과 본문 작성 흐름은 변경하지 않는다.
- 책 상세·검색 결과·첨부 책·책 선택창의 책장 등록 버튼과 제출 문구를 `책장에 담기`로 통일한다.
  영어는 `Add to shelf`로 통일하고 기존 locale 키를 재사용한다. `내 서재`와 등록 완료·활동 문구 및 등록 로직은 유지한다.

## 10. 모바일 작성 UX와 작성·수정 시각 표시

- 책 선택의 `선택 완료`는 선택 목록을 확정하고 창을 닫은 뒤 원래 작성 폼의 본문에 포커스를 준다.
  Turbo 왕복 후에도 같은 작성 문맥의 현재 textarea를 찾아 포커스하고 입력 영역을 스크롤해 보여 준다.
  0권 완료에도 적용하며 취소·닫기·뒤로 가기에는 본문 포커스를 강제하지 않는다.
  기존 본문·공개 범위·첨부 목록의 확정/취소와 초안 보존 정책은 유지한다.
- 첨부 목록은 작은 표지, 각각 한 줄 말줄임표인 제목·저자, 접근 가능한 책별 이름이 있는 작은 × 제거 버튼과
  작은 보조 `책장에 담기` 버튼으로 표시한다. 모바일에서도 가로 넘침·버튼 겹침 없이 배치하고 기존 제거·등록 권한과 동작을 유지한다.
  모바일에서는 제목·저자가 표지 옆의 남은 너비를 모두 사용하고, 그 아래 같은 액션 영역에 `책장에 담기`와 ×를 나란히 둔다.
  넓은 화면에서는 같은 액션 영역을 제목·저자 옆에 배치한다. 제거 버튼의 접근 가능한 이름·터치 영역과 소형 표지는 유지한다.
- 첨부할 책 선택 모달은 작성·수정 폼과 같은 공통 소형 표지를 사용하고 제목 크기와 기존 말줄임을 유지한다.
  제거는 작성 폼과 같은 작은 × 아이콘 버튼으로 표시하며 책 제목을 포함한 접근 가능한 이름, 터치 영역과 키보드 조작을 유지한다.
  선택 목록과 `선택 완료` 사이에는 권수에 관계없이 세로 여백을 둔다. 다른 책 목록과 선택·확정·취소 정책은 변경하지 않는다.
- 홈·프로필·동아리·책 상세·검색·발견의 일반 카드와 다시짹 자체에는 시각을 하나만 표시한다.
  미편집 글은 `%{time}에 작성함`, 편집 글은 `%{time}에 수정함`이며 최초 작성 시각을 함께 나열하지 않는다.
- `글 보기` 상세는 미편집 글에 작성 시각, 편집 글에 `작성 시각에 작성함 · 편집 시각에 수정함`을 표시한다.
  다시짹 원문도 같은 두 시각 정책으로 `○○님의 짹` 아래에 표시한다. 각 시각 문구 안에서 줄바꿈하지 않고
  좁은 화면에서는 두 시각 사이에서 줄바꿈할 수 있다. 다시짹 자체와 원문의 날짜는 각 카드 안에 구분한다.
- 공통 partial과 명시적인 상세 문맥을 사용하며 ko/en 기존 시각 locale을 재사용한다.
  편집 여부와 최종 편집 시각은 기존 `content_edited_at`만 따른다. 이 값은 성공한 본문 변경에만 기록되므로
  공개 범위·첨부만의 변경이나 무관한 `updated_at` 갱신은 본문 편집으로 표시하지 않는다.
  기존 값이 없는 과거 편집 이력은 추정하지 않는다. 새 컬럼·판별 정책·backfill을 추가하지 않으며
  `created_at`·`updated_at`·피드 정렬·삭제 tombstone의 작성/삭제 시각 표시는 유지한다.
- 검증은 모바일의 선택 완료(같은 화면/검색 왕복) 포커스·스크롤, 취소 초안 보존, 제거·등록과
  일반/상세/인용 시각 구분을 대상으로 한다. 기존 권한·통합 동작 테스트를 보존하며 실행은 사용자가 담당한다.

## 11. 검색 UI와 사용자용 짹 용어 일원화

- 내비게이션의 `검색`을 유지하고 `/search` 제목도 `검색`으로 표시한다. 책 찾기 메뉴·`/book_search` 제목·
  전역 책 검색 모달 제목은 기존 ko/en locale 키로 `책 찾기` / `Find books`를 표시한다. URL·라우트는 유지한다.
- 책 선택 모달과 일반 `/book_search`의 검색 실행 버튼은 공통 `book_search.form.submit`으로
  `책 찾기` / `Find books`를 표시한다. 통합 검색 `/search`의 `검색` 버튼과 기존 검색·검색어 유지 동작은 변경하지 않는다.
- 일반·첨부용 책 찾기 결과는 같은 공통 카드 구조·간격과 대형 표지를 사용하며 ISBN은 독자용 카드에서만 숨긴다.
  제목·저자/출판사·설명 아래의 같은 하단 액션 영역에 일반 결과의 기존 상세·책장 버튼 또는 첨부용 `추가`를 배치한다.
  선택된 책 표시와 추가 제한, 내부 ISBN 식별·검색·선택·서재 등록 동작은 변경하지 않는다.
- 첨부 책 선택 모드에서는 일반 책 찾기의 큰 제목·설명 카드만 숨긴다. 실제 검색 결과·검색 기능과
  `첨부할 책 선택하기` 패널, 완료·취소·뒤로 가기·포커스·초안 보존은 유지한다. 일반 책 찾기에는 제목 카드를 유지한다.
- 사용자용 게시물 종류는 첨부 유무·권수·과거 종류와 무관하게 `짹`이다. `다시짹`은 인용 관계를 설명하는 명칭이며
  별도 검색 유형이 아니다. 향후 이미지 등 첨부가 추가되어도 첨부 종류로 게시물 유형을 나누지 않는다.
- 일반 검색은 `전체 / 사용자 / 짹 / 동아리`와 `사용자, 짹, 동아리, #태그 검색` 안내를 제공한다.
  `jjaeks` 결과는 기존 일반·책·추천짹과 접근 가능한 다시짹을 하나로 조회하며 책 자체의 검색은 책 찾기에서 제공한다.
  태그 검색은 기존 정확한 태그 연결·동아리/사용자 범위를 유지하고 `전체 / 짹`으로 통합한다.
- 과거 `type=book_jjaeks`, `type=recommendation_jjaeks`는 `jjaeks`로 정규화한다. 알 수 없는 유형은 기존 전체 fallback을 유지한다.
  범위·대상 검증과 잘못된 요청의 404는 유지하며 구 파라미터로 서버 오류나 권한 우회가 발생하지 않게 한다.
- 기존 Pundit 검색 scope·두 사람 전용 대화·원문 접근 재검사·숨김/삭제 제외·댓글 제외·본문 검색을 유지한다.
  전체 미리보기는 통합한 짹 결과에서 최대 5건, 개별 탭은 기존 30/50/100건과 최신 작성 시각·ID 정렬을 유지한다.
- 관리자 분류는 12절을 따른다. 기존 권한·태그·범위·페이지네이션과 첨부 선택 모드의 제목 숨김을유지한다.

## 12. 관리자 모니터링과 콘텐츠 관리

- 시스템 관리자 배지는 댓글 → 다시짹 → 동아리짹 → 짹 순서로 판별하며 상호 배타적으로 하나만 표시한다.
  기존 `requote?`와 원문 삭제 marker를 재사용하므로 원문 삭제 후에도 다시짹이다.
  첨부 0~5권·과거 `book_id`/`recommendation`으로 배지를 나누지 않는다.
- `Admin::ContentHelper`와 공통 partial이 사용자·동아리 목록의 최근 활동과 콘텐츠 목록에서
  같은 라벨·색상·판별을 사용한다. 짹은 파랑, 동아리짹은 초록, 다시짹은 보라, 댓글은 노랑이다.
  콘텐츠 목록의 유형 열에는 배지만 표시하고 동아리 이름은 표시하지 않는다.
  사용자 콘텐츠 관리에서는 동아리 이름을 영역 열에 표시하고, 동아리 콘텐츠 관리에서는
  페이지 자체가 특정 동아리이므로 동아리 이름을 반복하지 않는다.
  사용자·동아리 목록의 최근 활동에서는 기존 동아리 이름 표시를 유지한다.
  배지는 상호 배타적으로 하나만 표시한다.  
- 사용자·동아리 관리자 상세 제목 카드에는 최근 활동 영역을 표시하지 않으며 상세 action의 전용 조회도 제거한다.
  목록의 최근 활동 조회·표시는 유지하고 기본 정보·관리 기능·콘텐츠 관리 링크는 보존한다.
- 사용자 상세는 별도 사용자 활동 카드를 제거하고 제목 카드 안에 `짹 21 · 동아리짹 9 · 다시짹 2 · 댓글 6`처럼
  일반 텍스트 링크로 집계를 표시한다. 숫자 배지나 개별 카드를 사용하지 않으며 각 링크는 기존
  `content=general / group / requote / comments` 필터로 연결한다. 기존 집계 데이터를 재사용하고 중복 조회하지 않는다.
  개인·동아리 일반 짹에서 다시짹을 제외하고
  개인·동아리 다시짹을 한 항목으로 센다. 기존 관리자 조회 범위·검색어·영역·상태 조건 안에서 집계하며
  유형 선택과 페이지 번호는 집계 범위를 나누지 않는다. 네 항목 합계는 같은 조건의 전체 활동 수와 같다.
- `/admin/users/:id/content`의 유형 선택은 영역 선택과 동일한 segmented navigation으로
  `전체 / 짹 / 동아리짹 / 다시짹 / 댓글`을 표시한다. 숫자가 있는 집계 카드를 사용하지 않으며
  선택 상태·기존 URL 파라미터·필터를 유지한다. 사용자 상세의 집계 로직은 유지한다.
- 사용자 콘텐츠 유형 필터는 `all / general / group / requote / comments`이며
  영역 필터와 함께 적용한다. 시스템 관리자 동아리 콘텐츠는 `all / group / requote / comments`다.
  일반 짹 필터에서는 다시짹을 제외한다. 동아리 관리자 전용 목록은 기존 정책을 유지한다.
  폐기된 유형 파라미터 등 지원하지 않는 값은 기존처럼 `all`로 처리한다.
- 시스템 관리자 콘텐츠 테이블의 `참고` 열은 제거한다. 본문 요약과 보조 정보는 각 한 줄 말줄임이다.
  두 시스템 관리자 콘텐츠 목록 모두 첨부가 없으면 책 보조 정보를 생략하고, 한 권은 첫 번째 책 제목,
  여러 권은 `첫 번째 책 제목 외 N권`(N=전체 권수-1)을 표시한다. 대표 책은 현재 짹 자신의 첨부 순서를 따르며
  다시짹 원문의 책을 합산하지 않는다. 같은 관리자 helper와 기존 연관 사전 로딩을 사용한다.
  다시짹·댓글은 원문 문맥과 무관하게 `원문 작성자 : 원문 일부`를 표시한다. 동아리 이름을 본문에 반복하지 않는다.
  첨부가 없거나 Comment이면 책 정보를 표시하지 않는다. 원문은 기존 관리자 조회 scope 안에서 일괄 로드한다.
- 삭제된 짹에는 보조 정보를 표시하지 않는다. 동아리 관리자의 platform-hidden 본문과 보조 정보도
  기존 목록 출력·검색 경계 안에서 숨긴다. 바로가기와 숨김/복원 등 기존 조치 및 권한은 유지한다.
- 삭제·제거된 원문의 요약은 표시하지 않는다. 일반 사용자·동아리 관리자에게 이 원문 조회를 적용하지 않는다.
- 목록의 최근 활동 선택 방식·시각, 사용자 항목 단위/동아리 thread 단위 집계·정렬·페이지네이션을 유지한다.
  분류별 집계에서 다시짹의 중복만 없애며 전체 활동을 누락하거나 중복 집계하지 않는다.
- 검색·발견·일반 사용자 피드, DB·저장 방식·moderation 정책은 변경하지 않는다.

## 13. 첨부 기준 조회의 회귀 검증

- 책 상세의 댓글 패널은 부모 Jjaek 인가 후 실제 첨부 연결로 책 문맥을 검사한다.
  단일·다중 첨부의 각 책에서 기존 열기·닫기·작성 Turbo 대상을 유지한다.
- 발견 후보는 첨부 연결 기준으로 분류하고 두 사람 전용 대화를 명시적으로 제외한다.
  책별 후보는 중복 없는 하위 쿼리로 조회하며 개인·동아리 미리보기는 최대 3권과 `외 N권`을 표시한다.
- 책친구 활동은 첨부 연결에서 조회하며 기존 친구·visibility·숨김·삭제·최신 3건 정책을 유지한다.
- 독서 상태·스티커는 단일 첨부의 실제 Book을 기준으로 기존 ReadingStateScope를 적용한다.
  여러 권 첨부에는 독서 상태 UI를 추가하지 않는다.
- 회귀 request spec은 `selected_books[]`로 실제 작성한 짹을 사용한다.


## 14. 작성·선택 경로와 검증

- 최종 작성·수정 입력은 `selected_books[]`다. 수정 요청에서 키를 생략하면 기존 첨부를 유지하고,
  명시적인 빈 선택은 제거한다. 구형 book_id/book_post_destination 게시 입력은 거부한다.
  `book_context_id`/`book_context_token`은 책 페이지의 복귀 문맥이며 첨부·게시 대상 입력이 아니다.
- `/jjaek_books`의 `JjaekBooksController#index/create/destroy`와 `BookSelection`은 임시 선택·문맥 인가,
  사용자 바인딩·30분 만료·외부 참조 해석을 담당한다. 최종 저장은 JjaeksController와 모델이 담당한다.
  `book-selection` Stimulus, permanent 선택창, `book_selection` Frame과 revision header는
  초안 보존·취소 복원·늦은 Turbo 응답 차단에 사용된다. 별도의 추천 작성 단계는 없다.
- 외부 책은 최종 저장에서만 기존 Book을 재사용하거나 생성한다. 메타데이터를 덮어쓰지 않으며
  Book·본문·첨부는 함께 성공하거나 롤백한다. 선택·검색만으로 DB 초안을 만들지 않는다.
- 책 선택창과 첨부 검색의 스크롤 영역을 분리한다. 모바일 패널은 최대 48dvh,
  데스크톱은 결과와 선택 패널을 나란히 배치해 검색창이 결과 버튼·페이지 링크를 덮지 않게 한다.
- 권한·A/B/C·삭제 책 정보·0/1/5권과 초과 거부·외부 참조·실패 원자성·첨부 순서·선택 취소·Back을 검증한다.
  운영 백업본 전환과 이전 이미지/DB 복구는 [별도 환경 리허설](../ops/deploy_oci.md#데이터-전환과-복구-리허설)을 통과한 뒤 배포한다.
