# 통합 검색

## 범위와 UI

- 로그인 사용자는 내비게이션의 검색 메뉴로 독립 페이지 `GET /search`에 접근한다.
- 검색어 `q`, 유형 `type`, 표시 개수 `per_page`, 페이지 `page`를 URL에 유지한다. 유형은 `all`(기본), `users`, `jjaeks`, `book_jjaeks`, `groups`다. 알 수 없는 유형은 전체로 처리한다.
- 사용자 이름·공개 handle, 일반 짹 본문, 책짹 본문, 동아리 이름을 검색한다. 짹/책짹은 게시물 자신의 `book_id` 유무로 구분하며 다시짹도 현재 조회 권한 안에서 포함한다.
- 검색어 앞뒤 공백을 제거하고 PostgreSQL `ILIKE`로 대소문자 구분 없는 부분 문자열 검색을 한다. 한글 문자열을 지원하며 형태소·초성 검색은 제공하지 않는다. `%`, `_`, `\`는 검색 문자의 일부로 취급한다.
- 검색어가 비면 결과 조회 없이 입력 안내를 표시한다. 일치 결과가 없으면 빈 결과 안내를 표시한다.
- 전체 탭은 유형마다 최대 5건과 해당 유형 전체 보기 링크를 제공한다. 개별 탭은 기존 `Admin::InventoryPage`와 공통 pagination partial을 재사용하고 30·50·100건 중 선택한다. 기본값과 허용되지 않은 값의 fallback은 30건이다.
- 기존 page size partial과 `page-size` Stimulus를 재사용해 선택 변경 시 GET 폼을 제출한다. 검색어 변경·유형 전환·전체 보기·표시 개수 변경은 첫 페이지부터 조회하고 선택한 표시 개수를 유지한다. JavaScript 없이도 검색 버튼으로 제출할 수 있다. 전체 탭의 유형별 5건 제한은 `per_page`와 독립적이다.
- 사용자·동아리는 이름순, 짹·책짹은 최신순으로 정렬하고 ID를 보조 정렬키로 사용한다.
- 사용자 결과는 기존 아바타 helper와 사용자 목록 스타일로 이름·공개 handle·프로필 링크 및 기존 용어의 소식받기 수를 표시한다. 책친구·내가 소식 받는 사람·내 소식을 받는 사람 배지는 현재 관계가 성립할 때만 함께 표시하며 자기 자신에게는 표시하지 않는다. 관계 변경 버튼은 제공하지 않는다.
- 짹·책짹 결과는 기존 `jjaeks/jjaek` 카드의 읽기 전용 미리보기를 사용해 작성자 아바타·이름·작성 시각·공개 범위·본문을 표시한다. 책짹은 기존 표지·제목·저자와 현재 열람 가능한 독서 상태·스티커를 표시한다. 인용 원문은 표시하지 않으며 좋아요·댓글·다시짹·수정·삭제 동작을 추가하지 않는다.
- 동아리 결과는 기존 `groups/group_card`를 사용한다. 기존 Group 목록 scope로 접근 가능한 동아리는 공개 상태·운영 상태·관리자·회원 수와 최대 3명의 active 일반 회원 아바타를 표시한다. 관리자와 pending/invited 회원은 기존 회원 수·미리보기 기준대로 제외한다. 접근할 수 없는 비공개 동아리는 이름·공개 상태·상세 링크만 표시한다.
- 게시물 상세의 뒤로가기는 기존 검증된 `return_to` 흐름을 사용해 검색어·유형·표시 개수·페이지를 유지하며 그 외 검색 URL parameter는 전달하지 않는다.
- PC·모바일에서 기존 Tailwind 버튼·카드 스타일을 사용하고 한·영 문구를 제공한다.
- 댓글 검색, 기존 책 검색·책 선택 변경, 무한 스크롤, 새 검색 엔진·Gem·데이터 모델은 범위에 포함하지 않는다.

## 권한과 정보 경계

- 페이지 접근은 `SearchPolicy`, 결과 조회는 대상별 Pundit scope로 제한한다. 결과를 가져온 뒤 Ruby에서 권한을 걸러내지 않는다.
- 사용자 검색은 탈퇴하지 않은 계정의 공개 이름·handle만 대상으로 한다. 이메일과 비공개 개인정보를 검색하거나 출력하지 않는다. 기존 프로필 열람 정책을 확대하지 않는다.
- 짹·책짹은 기존 `JjaekPolicy::Scope`를 재사용하고 숨김·삭제 항목은 제외한다. 본문 조건은 권한 scope 적용 뒤 추가하여 인용 원문이 검색어와 일치하지 않아도 현재 원문 열람 권한을 정확히 검사한다.
- 개인 콘텐츠의 전체 공개·책친구 공개·나만 보기 및 profile target 경계를 유지한다. 운영 관리자에게 일반 검색 전용 우회를 추가하지 않는다.
- 동아리 콘텐츠는 기존 Group membership·운영 lifecycle·원문 접근 조건을 따른다. 비회원에게 비공개/승인 동아리 내부 콘텐츠를 노출하지 않는다.
- 살아 있는 인용 원문의 관계·공개 범위·숨김 변화는 기존 다시짹 scope로 재검사한다. 원문 삭제 후 개인 다시짹 A와 동아리 다시짹 B/C 처리는 `group_sharing_requotes.md`를 유지한다. 검색은 게시물 자신의 본문만 대상으로 하며 원문 본문·삭제 원문 snapshot을 미리보기에 표시하지 않는다.
- 동아리 이름 검색은 기존 Group 목록 scope에 **운영 중인 모든 유형의 동아리 이름**을 더하는 `GroupPolicy::NameSearchScope`를 사용한다. 비공개 동아리의 일반 발견 제외 정책에 대한 통합 검색 한정 예외다. 운영 종료·신청·거절·취소 상태의 동아리는 기존 목록 권한이 있는 사용자에게만 검색된다.
- 이름 검색 허용은 상세·내부 정보 열람 허용과 별개다. 접근할 수 없는 비공개 동아리 결과에서 소개·관리자·회원 수·미리보기·내부 콘텐츠를 노출하지 않으며 기존 `show?`와 콘텐츠 권한을 변경하지 않는다. 권한 없는 비공개 동아리의 상세 링크 접근은 기존처럼 거부된다.
- 사용자 관계와 소식받기 수는 현재 페이지의 사용자 ID에 한정해 일괄 조회한다. 동아리 관리자·회원 미리보기는 기존 Group 목록 scope로 제한해 조회하고 기존 window query를 공유한다. 아바타와 현재 독서 정보도 미리 로드하여 카드별 추가 쿼리를 만들지 않는다.

## Acceptance Criteria

- 네 가지 대상, 전체/개별 탭, 빈 검색어·일치 없음, 한국어 부분 일치와 URL 유지가 동작한다.
- 책친구·비공개·동아리·다시짹의 현재 권한을 SQL 조회 단계에서 적용하고 숨김·삭제 본문과 권한 없는 작성자·미리보기를 노출하지 않는다.
- 공개 handle로 사용자를 찾을 수 있고 이메일로 찾거나 개인정보를 출력하지 않는다.
- 비공개 동아리 이름·공개 상태는 검색되지만 비회원에게 관리자·회원 정보를 노출하지 않고 상세·내부 콘텐츠 접근도 계속 거부된다.
- 상세 링크와 페이지 이동이 동작하며 페이지 범위 밖·잘못된 페이지는 기존 페이지네이션 규칙으로 정규화한다.
- 전체 탭은 유형별 최대 5건, 개별 탭은 선택한 30·50·100건까지만 가져오고 게시물 작성자·책 정보를 미리 로드한다. 페이지 이동·표시 개수 변경과 상세 복귀에서 검색 URL 상태를 보존한다.
