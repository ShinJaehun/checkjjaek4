# C08 이메일 초대 기반 회원가입

## 목적과 범위

베타 기간의 신규 일반 User 가입은 시스템 관리자(`global_admin`)가 발송한 이메일 초대로만 시작한다. 기존 User의 로그인과 활동, Devise 계정 수정·비밀번호 재설정, GroupMembership 초대는 그대로 유지한다. 관리자 직접 User 생성 UI/API와 운영 메일 제공업체·도메인·DNS 설정(E11)은 이 범위에 없다.

## 정책

- 시스템 관리자만 회원가입 초대 목록, 발송, 재발송, 취소를 수행한다. Pundit policy와 scope가 권한을 강제한다.
- 이메일은 공백 제거·소문자화하여 보관한다. 이미 User가 있거나 사용·취소되지 않은 같은 이메일 초대가 있으면 새 초대를 만들지 않는다. 만료된 초대는 재발송해 기한을 갱신한다.
- 초대 링크는 발송 또는 재발송 시점부터 7일간 유효하다. 충분히 긴 무작위 token의 SHA-256 digest만 DB에 저장한다. 재발송하면 이전 token이 즉시 무효화된다.
- 사용 완료 또는 취소 상태의 링크는 무효다. 취소한 이메일에는 새 초대를 발송할 수 있다. 사용 완료 초대는 감사용으로 남는다.
- 자발적 탈퇴 시 해당 User와 연결된 초대 및 같은 이메일의 과거 초대는 이메일을 초대별 비식별 주소로 교체하고 User 연결을 해제한다. 기존 종료 상태와 발송·사용·취소 시각은 유지하며, 예외적으로 활성 초대가 남아 있다면 취소해 링크를 무효화한다. 원래 이메일을 복원할 수 있는 값이나 단순 해시는 남기지 않는다. 미사용 초대의 일반 보존기간은 별도 정책으로 정한다.
- 초대 링크가 유효해야 회원가입 화면과 `POST /users`를 사용할 수 있다. 초대 이메일은 서버가 User에 할당하며 제출된 이메일은 무시한다.
- 가입 시 기존 이름·handle·비밀번호 검증과 필수 이용약관 동의를 적용한다. 동의 시각과 약관 버전은 새 User에 기록하며 기존 회원의 로그인·계정 수정에는 이 검증을 적용하지 않는다. User 저장과 초대 사용 처리는 같은 DB transaction과 초대 행 잠금 아래 수행한다. DB의 User 이메일·handle 고유 인덱스와 초대의 pending 이메일 고유 인덱스가 동시 요청의 중복을 막는다.
- 초대 수락으로 생성되는 User는 일반 User다. 로그인 중인 관리자도 가입 endpoint로 다른 User를 직접 만들 수 없다.
- 초대 원본 token과 비밀번호는 로그에 남기지 않는다. 발송은 Action Mailer를 사용하며 개발·테스트에서 확인할 수 있다.

## 수용 기준

1. 비로그인 사용자와 일반 User는 관리자 초대 화면 및 변경 요청에 접근할 수 없다.
2. 초대 발송 메일에만 가입 URL의 원본 token이 들어가며 DB에는 digest가 남는다.
3. 만료·재발송 전 링크·사용 완료·취소 링크와 초대 없는 POST가 가입을 만들지 않는다.
4. 다른 이메일이나 `global_admin`을 제출해도 초대 이메일의 일반 User만 생성된다.
5. 동의 누락을 포함한 검증 실패는 초대를 소비하지 않는다. 성공 시 User의 동의 시각·버전과 초대 사용이 함께 commit된다.
6. 같은 링크를 두 요청이 동시에 사용해도 하나의 User만 생성된다.
7. 기존 회원은 계속 로그인할 수 있다.
8. 자발적 탈퇴 후 초대 기록에 원래 이메일과 탈퇴 User 연결이 남지 않으며, 같은 이메일로 새 초대를 발송할 수 있다.
