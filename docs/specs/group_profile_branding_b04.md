# B04 — 동아리 대표 이미지·배너 이미지·대표 색상

사용자가 승인한 구현 범위다. 배포·migration·RSpec·브라우저 검증 완료를 의미하지 않는다.
기존 Group lifecycle·조회·관리 권한은 `groups_mvp.md`, 접근 구조는
`../architecture/authorization.md`를 따르며 이 변경으로 확대하지 않는다.

사용자에게 표시하는 명칭은 **배너 이미지**(영어: **Banner image**)다.
내부 모델 속성·첨부 이름 `cover_image`, locale 키와 저장·접근 권한 로직은 유지한다.

## 표시와 관리

- 기존 동아리 관리 화면에서 대표 이미지와 배너 이미지를 각각 업로드·교체·삭제한다.
  기존 `GroupPolicy#update?`를 사용하므로 현재 동아리 관리자에게만 열리고 운영 정지 중에는 변경할 수 없다.
  새 동아리 신청 폼의 범위는 유지하며 생성 후 관리 화면에서 설정한다.
- 관리 화면은 사용자 설정과 같은 테두리·모서리·흰 배경·그림자·패딩·제목 크기로
  제목/상태, **동아리 정보**(이름·소개), **동아리 꾸미기**(대표·배너 이미지·색상) 카드를 구분한다.
  정보·꾸미기는 각각 독립된 폼으로 기존 `PATCH group_path(group)`에 저장하며 자체 저장·취소 버튼을 둔다.
  정보 폼은 이름·소개만, 꾸미기 폼은 대표·배너 이미지·삭제 표시·대표 색상만 제출한다.
  누락된 필드는 수정하지 않으며 실패한 폼에 오류를 표시하고 해당 입력과 기존 이미지를 보존한다.
  승인 대기 동아리의 기존 개설 목적 수정은 별도 영역·폼으로 보존한다.
  운영 종료·재운영·운영 이력도 폼 밖 별도 영역을 유지한다.
  생성 화면은 같은 정보 입력 partial을 재사용하고 기존 개설 유형·목적·신청 동작을 유지한다.
  사용자·동아리 대표 이미지의 미리보기는 96px, 설명은 형식·5MB 용량만 간결하게 표시한다.
  사용자 아바타도 이미지 오른쪽 상단에 같은 작은 원형 X와 44px 터치·키보드 영역을 사용한다.
  기본 아바타에는 삭제 X를 표시하지 않고, 새 파일 미리보기 중에만 선택 취소 X를 표시한다.
  새 파일 X는 선택만 취소하고 저장된 이미지로 복귀하며 Object URL을 회수한다.
  업로드한 저장 이미지의 X는 기존 별도 DELETE 요청으로 즉시 삭제한다.
  `avatar-preview`의 형식·용량 검증과 파일 선택 취소·Turbo cache 복귀 처리는 유지한다.
  대표·배너 이미지 파일을 선택하면 제출 전 즉시 미리보기를 표시한다. 이미지 오른쪽 상단의 작은 원형 X는
  44px 터치 영역·키보드 포커스·상태별 접근 가능한 이름을 제공한다.
  새 파일의 X는 선택만 취소하고 저장된 이미지로 돌아간다. 저장된 동아리 이미지의 X는
  짧은 **삭제 예정** 상태와 삭제 취소 버튼만 표시하며, 실제 삭제는 꾸미기의 **저장** 제출이 성공했을 때 수행한다.
  삭제 예정 상태에서 새 파일을 고르면 삭제 표시를 해제해 교체와 삭제가 동시에 요청되지 않는다.
  저장 실패 시 기존 이미지를 다시 표시한다. `group-image-preview` Stimulus controller는
  선택 변경·취소·디코딩 실패·연결 해제 시 Object URL을 반환하고 Turbo cache 전에는 임시 상태를 초기화한다.
- 동아리 관리의 제출 문구는 **저장**이다. 동아리 관리·순서 편집의 저장/취소는 각각
  `ui-button ui-button-primary` / `ui-button ui-button-secondary`를 사용하고
  같은 `flex flex-wrap items-center gap-3` 정렬·간격과 기존 공통 포커스 스타일을 따른다.
  다른 화면의 버튼 클래스와 생성 화면의 버튼 문구는 유지한다.
- 대표 이미지는 상세 타이틀 정보 영역의 왼쪽에 모바일 64px·그 이상 96px로 표시한다.
  현재 회원 목록·접근 가능한 검색 카드에는 48px, 발견의 추천 동아리에는 56px(`h-14 w-14`) 정사각형 썸네일을 표시한다.
  미등록 상태와 이름만 공개되는 비공개 검색 결과는 둥근 사각형의 `users-round` 아이콘을 사용한다.
  추천 동아리의 기본 아이콘도 56px 영역을 사용하며 다른 화면의 대표 이미지 크기는 유지한다.
  `/groups`의 과거 참여 카드와 초대의 식별 정보 범위는 확대하지 않는다.
- `/groups/membership_order/edit`의 현재·목록에서 제외한 동아리와 과거 동아리 항목 왼쪽에도
  `groups/profile_image`로 48px 대표 이미지 또는 기본 아이콘을 표시한다.
  과거 동아리는 기존 `GroupPolicy::Scope`와의 교집합에만 이미지 첨부를 preload하며,
  상세 접근 권한이 없는 과거 동아리는 이미지 URL 없이 기본 아이콘만 표시한다.
  기존 정렬 항목·입력·드래그·모바일 위/아래 이동·저장과 제외/복원 흐름은 유지한다.
- `/jjaeks/new`의 다시짹할 동아리 선택 카드는 기존 게시 가능·미사용 목적지 목록을 유지하며
  대표 이미지 또는 기본 아이콘 48px, 이름 아래의 공통 유형 배지와 4px 대표 색상 띠를 표시한다.
  공개 범위 안내와 선택된 카드의 테두리·배경, 전체 label 클릭·키보드 선택·required 검증을 유지한다.
  링크가 있는 일반 동아리 카드로 바꾸지 않고 표시 partial만 재사용하며 목적지의 대표 첨부를 일괄 preload한다.
- 배너 이미지는 일반 동아리 상세 타이틀 상단의 가로 배너에만 표시하고 중앙 기준 `object-cover`를 사용한다.
  미등록 시 단색 배경을 표시한다. 제목·유형·상태·회원·관리 버튼은 배너 아래 별도 영역에 둔다.
- 두 이미지는 JPEG·PNG·WebP, 파일당 최대 5MiB(5,242,880 bytes)다. 실제 파일 형식과 디코딩을 검증한다.
  기존 A17과 같은 4천만 픽셀 상한으로 과도한 디코딩을 거부한다. 사용자용 크롭·배너 편집기는 추가하지 않는다.
- 대표 색상은 stone/red/orange/amber/emerald/teal/blue/violet의 8개 키 중 선택한다.
  임의 HEX·CSS는 허용하지 않으며 모델과 DB CHECK로 검증한다. 미설정 동아리는
  `id % 8`로 팔레트의 기본색을 안정적으로 선택하며 일괄 backfill하지 않는다.
- `/groups`의 내 동아리 일반·과거 카드, 최근 동아리 소식과 `/groups/:id`의 짹 피드 카드 안쪽 왼쪽에
  공통 `groups/color_stripe` partial로 4px 색상 띠를 표시한다. 과거 카드의 최소 조회 필드에 `brand_color`를 포함한다.
  다시짹도 `quoted_jjaek.group`이 아닌 게시물 자체의 `group` 색상을 사용한다.
  동아리 상세 피드에서는 일반·책 첨부·다시짹 모두 표시하고, 다시짹 안의 인용 원문에는 별도 띠를 추가하지 않는다.
  기존 이름·링크·둥근 모서리·테두리·여백·상태 배지·회원 표시·과거 상태 표현을 유지한다.
  홈·개인 프로필·검색·단건 짹 상세와 순서 편집 화면에는 띠를 추가하지 않는다. 무한 스크롤과 짹 작성 실패 후 상세 화면도 같은 범위를 따른다.

## 저장과 접근 통제

- `Group#profile_image`와 `Group#cover_image`는 독립된 Active Storage 단건 첨부다.
  `GroupImageChanges`가 업로드 파일만 받고 signed Blob ID·다른 부모의 첨부 재사용 입력은 거부한다.
  파일은 metadata를 제거한 WebP로 정규화하며 대표 이미지는 최대 512px, 배너 이미지는 최대 1600px로 줄여 저장한다.
  운영은 기존 비공개 `oci_photos` 서비스를 재사용하고 로컬·테스트는 기존 환경의 서비스를 사용한다.
- Blob에 동아리·이미지 종류를 기록하고 모델과 이미지 제공 경로에서 검증한다.
  이미지 처리·업로드 후 User → Group 순서로 행을 잠그고 계정 상태와 동아리 관리 권한을 재검사한다.
  교체·삭제할 이미지마다 폼을 열었을 때의 attachment ID(미등록은 빈 값)를 현재 첨부와 비교한다.
  불일치하면 꾸미기 전체 저장을 거절하고 현재 이미지와 충돌 안내를 표시한다.
  일치하면 설정·첨부 변경을 한 transaction으로 저장한다.
  검증·업로드 실패 시 기존 설정·첨부를 보존하며 새 파일은 정리 대상으로 남긴다.
- `GET /groups/:group_id/images/:id?size=...`는 로그인과 `GroupPolicy#view_images?`를 매 요청 검사한다.
  이 권한은 기존 `show?`와 같다. 따라서 승인 동아리의 공개 소개 이미지는 로그인 독자에게 보이고,
  비공개 동아리는 기존 상세 접근 권한이 있어야 보인다. 이름 검색 예외는 이미지 권한이 아니다.
  전역 관리자의 기존 운영 조사 접근도 유지한다.
- 첨부 ID는 요청 동아리의 대표/배너 이미지 첨부로 한정한다. profile은 card 128×128·detail 192×192,
  cover는 1280×384의 고정 Variant만 허용하며 원본·임의 크기 요청은 거부한다.
  변환 대기 후 현재 계정 상태, Group 권한과 첨부 소속을 재검사한다.
- 기존 `AuthenticatedImageDelivery`로 OCI URL redirect 없이 chunk 단위 중계하며 `private, no-store`를 적용한다.
  기본 Active Storage Blob/representation/Disk/direct-upload 라우트는 닫힌 상태를 유지한다.
  아바타 경로도 동아리 이미지 Blob과 Variant를 거부한다.
- 목록·검색의 접근 가능한 동아리에만 대표 첨부를 일괄 preload한다. 재운영 승인 대기 중 상세 접근 권한이 없는 회원에게는
  내 동아리와 순서 편집 카드에서 기본 아이콘을 표시한다. 배너 이미지는 목록·검색·발견에서 조회하지 않는다.
  기존 libvips 동시성·캐시 제한과 `ImageProcessingLock`을 그대로 사용한다.
- 교체·삭제 commit 뒤 `PurgeGroupImageJob`으로 원본·Variant를 정리한다.
  파일 삭제 성공 전 Blob 행을 지우지 않아 저장소 실패를 재시도할 수 있다.
  `CleanupGroupImagesJob`은 하루 이상 미첨부 파일을 정기 회수해 요청 중단도 처리한다.

## 검증과 환경

- `spec/requests/group_branding_spec.rb`: 두 이미지의 업로드·독립 교체·삭제, 실패 보존,
  형식·크기·signed Blob 거부, 관리자·운영 정지, 비공개 접근·회원 탈퇴·부모 및 공개 URL 우회,
  상세·목록·검색 표시, `/groups` 색상과 다시짹 목적지를 확인한다.
- 후속 UI 검증은 같은 request spec의 현재·과거 카드, 동아리 상세의 일반·책 첨부·다시짹과
  다른 피드 비적용에 추가한다. `spec/system/group_branding_preview_spec.rb`의 한 흐름으로
  대표·배너 이미지의 즉시 미리보기·선택 취소·삭제 예약/취소·교체 충돌 해소·실패 보존·제출 삭제와 Object URL 회수를 확인한다.
- 카드별 폼의 제출 필드·독립 저장·실패 시 오류 위치·기존 이미지 보존·생성 단일 폼은 같은 request spec으로 검증한다.
  `spec/system/avatar_preview_spec.rb`는 기존 검증·취소·Turbo 복귀 검증을 보존하며
  기본 아바타의 X 비노출, 새 선택 X의 취소와 저장된 이미지 X의 즉시 삭제·키보드 동작을 확인한다.
- 순서 편집의 이미지·과거 동아리 접근별 fallback과 다시짹 선택 카드의 업로드 이미지는
  같은 branding request spec에 추가한다. 기존 `spec/requests/group_sharing_requotes_spec.rb`의
  허용 목적지·제출·실패 시 선택 유지 검증을 보존하며 유형 배지·색상·기본 아이콘·링크 비포함을 확인한다.
- `spec/models/group_spec.rb`: 색상 저장·허용값 검증·ID 기반 기본색을 확인한다.
- 색상 컬럼과 CHECK를 추가하는 migration이 필요하다. 이미지용 DB 테이블은 기존 Active Storage를 사용한다.
  새 환경변수·bucket·스토리지 서비스는 필요 없다. 기존 `OCI_PHOTO_BUCKET`의 비공개 설정,
  OCI 접근 자격 증명과 libvips·Solid Queue 실행 환경을 유지하고 새 정리 작업을 기존 scheduler에서 실행한다.
- 사용자 검증: 모바일/PC 상세 배너·정보 분리, 기본 아이콘, 업로드·교체·삭제와 실패 메시지,
  동아리 꾸미기의 두 이미지 미리보기·X·삭제 예정/취소·키보드 조작·저장 실패 보존,
  목록·검색·발견 썸네일, 비회원 직접 URL·탈퇴 후 접근 차단, 8색 선택,
  현재·과거 카드와 동아리 상세 피드의 색상·다시짹 목적지·무한 스크롤, 다른 피드 비적용을 확인한다.
  순서 편집의 48px 이미지·기본 아이콘·과거 동아리 권한·PC 드래그·모바일 이동·저장,
  다시짹 선택 카드의 유형·색상·공개 안내·전체 클릭·키보드·필수 선택·실패 후 선택 유지를 확인한다.
  운영 배포와 외부 Google 문서 백로그 수정은 범위 밖이다.
